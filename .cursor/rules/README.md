# 项目 Rules（L0）

**结论（已验证·架构决策）**：`L0-01`～`L0-05` 保持为 **`alwaysApply: true` 的 rules**，**不**整批改成 Agent Skills。

| | Rules（本目录） | Skills（`../skills/`） |
|---|---|---|
| 用途 | 每回合硬约束（术语、证据、讲解、沟通、命名） | 按任务加载的厚流程 / 检查表 |
| 为何不搬迁 | 改成 skill 后未触发任务时反而不注入，聊天里更容易忘 | 适合「写 Docs 时再过门闩」等补强 |

补强（不替代本目录）：项目 skill `L0-doc-terminology-gate`——写/改 `Docs/**` 等面向用户 Markdown 时强制过 L0-01～03 自检。

详见计划结论：Rules 与 Skills 取舍（保留 rules 底座 + 文档门闩 skill）。

## L0-01 与 L0-02：不合并（架构决策 · 推断）

**不**把「思考与讲解」（01）与「术语与验收」（02）整并成一条 rule；不重编号 03～05。

| 点 | 说明 |
|---|---|
| 为何不并 | 两份 alwaysApply 与一份等长正文，注入量相近；合并不解决「长对话稀释 + 未跑交付自检」 |
| 冲突怎么解 | 「短 vs 术语全释」靠 **02 文首优先级**（02 压过 01/04）+ 门闩 skill，不靠并文件 |
| 何时再议 | 门闩仍反复失败时，再考虑单文件写作约束并一次性改引用——**现在不做** |
