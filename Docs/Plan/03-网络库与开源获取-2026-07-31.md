# 03 · 网络库与开源获取

> **现行计划（本能力）**：在永久库 / 容器之外新增**网络库**——本机只读缓存层，用于发现与同步开源 skills / rules；经单向桥梁写入永久库后才可编辑与部署。  
> 产品机制背景见 [01-核心逻辑](../01-核心逻辑.md)；竞品语境见 [Research/02](../Research/02-CCM竞品与产品定位-2026-07-31.md)（v1.1 已与本计划对齐）。  
> **对 Research/02 的修正（已采纳）**：「不做云协作与账号体系」；**允许**只读网络库作橱窗；**禁止**做成 Skills Manager 式「中央库 + 一键装 15+ Agent」主战场。

**调研日期口径**：2026-07-31  
**状态**：v1.3 — **Must（P0+P1）已交付并手测收口**（2026-07-31）；Should/Could 仍待排期

---

## 总论

**结论（建议）**：网络库定位为「检疫橱窗」——搜得到、看得见公开热度、可检查更新、用户确认后再缓存；**晋升**到永久库后才进入 CCM 护城河（编辑 / 冲突决议 / 部署）。不与 Skills Manager / Praxl 拼市场广度与双向云同步。

## 0. 竞品启示 → 对本计划的优化（建议）

**结论（建议）**：Research/02 的空白仍是「定稿对账」，不是「装机市场」；Plan/03 必须用边界与分期把网络能力收成**输入漏斗**，避免稀释差异化。

| 竞品信号（Research/02） | 对 Plan/03 的优化 |
|-------------------------|-------------------|
| Skills Manager：市场 + 多工具 symlink/复制同步已红海 | 网络库**不**做「装到各 Agent」；**禁止**网络缓存 symlink/直部署容器；晋升后才走永久库→容器 |
| Praxl：双向云同步 + 版本史 + AGPL 自托管 | 只要本机缓存 + 可选检查更新；**永不**自动改永久库；适配器**不**引入 AGPL 依赖 |
| AIS / rulesync：Git/规范源 → 多工具文件 | MVP 优先「官方基线 + 用户粘贴 Git URL」；skills.sh 类索引降为 Should（API/ToS **待验证**） |
| Manage My Skills：冲突时时间戳备份 | 覆盖网络库缓存前若指纹冲突 → **先 `.bak` 再写**（Should） |
| 行业短板：同名多版人选弱 | 存入永久库同名不同哈希 → **强制复用现有冲突窗**（文案「来自网络库」） |
| 离线优先 / 心智占位风险 | 启动与对账**不依赖**网络；导航忌「Marketplace」主品牌词 |

**不做（相对竞品的刻意留白）**：自建中央市场后端、云账号、AI 改写 skill、网络库内编辑、永久库回写网络、15+ Agent 一键矩阵同步。

## 1. 目标与用户价值

**结论（建议）**：在不污染永久库的前提下发现并跟上开源技能/规则；判断靠公开热度信号，更新靠用户确认；**价值终点是「安全晋升为定稿」而非「浏览市场」**。

| 项 | 内容 |
|----|------|
| 核心意图 | 获取开源 skills / rules（含各工具**官网**作为最基础源） |
| 存放 | 本机**新建**独立根目录 = **网络库**（与永久库根分离） |
| 决策辅助 | 展示源公开的热度、下载量、趋势字段（无则「—」，禁止虚构） |
| 同步 | 可自动**检查**远端更新并提示；是否覆盖**网络库缓存**由用户选择 |
| 桥梁 | 网络库 → 永久库；**永久库 → 网络库 禁止** |

## 2. 三库模型与硬边界

**结论（建议）**：语义固定三层；不得打破单向箭头。

```text
远端源（官网 / Git URL / 开源索引…）
        │  搜索 · 拉取 · 检查更新（只读缓存写入）
        ▼
   【网络库】本机检疫橱窗 · 不可编辑 · 不可部署容器
        │  用户显式「存入永久库」（可经冲突窗）
        ▼
   【永久库】定稿 · 可编辑 · 台账 SSOT · 冲突人选
        │  部署 / 撤回 / 刷新对账（现有能力）
        ▼
   【容器】工具实际读取 · 才生效
```

| 规则 | 说明 |
|------|------|
| 网络库不可编辑 | 无保存写回；预览只读 |
| 永久库不可导入网络库 | 无回灌/上传为网络条目 |
| 网络库不直达容器 | 禁止复制/symlink 到容器 |
| 台账隔离 | 永久库 `catalog.json`；网络库独立索引 |
| 路径隔离 | 网络库根 ≠ `skills_library_root` |
| 离线主路径 | 无网时永久库/容器全流程可用 |

**口诀**：网络库 = 检疫橱窗；永久库 = 自家定稿；容器 = 上架生效。

## 3. 功能范围（MoSCoW）

**结论（建议）**：Must 收窄为「官网 + Git 粘贴 + 晋升闭环」；公开索引与热度排序放 Should。

| 优先级 | 功能 |
|--------|------|
| **Must** | 网络库根与独立索引；**官网/官方示例仓基线**；**用户粘贴 Git URL 拉取**；浏览已缓存条目；元数据（名称、skill/**rule**、来源 URL、摘要、许可若可得）；检查更新 + 用户选更新/跳过/稍后；「存入永久库」+ 同名走现有冲突三钮；只读可测 |
| **Should** | skills.sh 等公开索引（ToS/API 核对后）；热度/下载列与排序；定时仅检查；覆盖缓存前 `.bak`；批量存入；远端新版提示「可再次晋升」；缓存清理 |
| **Could** | 更多源；简易趋势图；关注源；随应用分发的「官方精选」静态列表 |
| **Won't(now)** | 云账号/团队；网络库编辑；永久库回写网络；自建市场后端；整站爬虫；网络→多 Agent 一键同步；AGPL 依赖；AI 改写正文 |

## 4. 数据与同步语义

**结论（建议）**：检查更新与覆盖缓存分离；永久库永不被网络静默改写。

| 概念 | 是什么 | 起什么作用 |
|------|--------|------------|
| 远端 ID | URL / 仓库路径 / 官方 slug | 跨次对齐同一条目 |
| 缓存正文 | 网络库只读副本 | 离线浏览 |
| 远端指纹 | version / commit / etag / 哈希 | 判断有更新 |
| 更新状态 | current / updateAvailable / skipped / error | 角标与批量 |
| 热度指标 | 源公开下载量/星标/趋势等 | 排序；无则「—」 |

1. 元数据可较频刷新。  
2. 正文：首次 / 用户点更新 / 显式「自动下载缓存更新」。  
3. 自动检查默认只标记，不覆盖正文。  
4. 覆盖缓存前（Should）：指纹冲突则先 `.bak`。  
5. 存入永久库后脱钩；远端再新不自动改永久库。

## 5. UI / 导航（产品面）

**结论（建议）**：分区名「网络库（开源橱窗）」；主按钮「存入永久库」「检查更新」；忌 Marketplace 主文案。

- 列表含 rule 类型、来源、热度（可 —）、更新角标  
- 详情只读；禁止可保存编辑页签  
- 设置：网络库根、源开关、检查间隔、是否自动下载**缓存**  
- 无网：用缓存；拉新失败不影响其它分区

## 6. 与现有能力的衔接

**结论（建议）**：把竞品缺少的「人选」变成晋升标准步骤。

| 现有能力 | 衔接 |
|----------|------|
| 迁入/入库 | 存入 = **复制**（非 symlink）+ upsert；`origins` 标 network + URL |
| 部署/撤回/刷新 | 仅永久库；网络条目无 deployedPath |
| 冲突窗 | 同名不同哈希 → 三钮；文案「来自网络库」 |
| 五槽备份 | 默认不备份网络库 |

## 7. 源适配与合规（约束）

**结论（建议）**：官网 + Git URL 为 Must；第三方索引进 Should；禁止 AGPL 链入发行。

| 约束 | 要求 |
|------|------|
| 许可/归因 | 能取则展示；保留来源 URL |
| 依赖 | MIT/Apache 等清晰许可客户端 |
| 频率/安全 | 限速；不当脚本执行；拒路径穿越 |

MVP 源序：**待验证**可用性 — ① 官网/示例仓 ② 粘贴 Git URL ③ skills.sh 类（Should）。
