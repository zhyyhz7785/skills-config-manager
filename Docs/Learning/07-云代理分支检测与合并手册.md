## 2. 内容分层（合并时怎么取舍）

| 层级 | 主要在哪 | 内容一句话 |
|---|---|---|
| L1 网络库货架 | fqzoo ≡ network；m30of 亦含 | `NetworkShelf`、`network_p2`、安全/定制/晋升… |
| L2 Plan/05 错位超越 | **仅 m30of**（相对 network 约 +2000 行） | 漂移报告、部署配方、`cli_api`、工作区扩、E008/E009、帮助 06、包号等 |
| L3 mw2rn 边角 | **仅 mw2rn** | `list_cluster` / `open_entries` 改动；`deploy` 与 m30of 不同稿 |

**取舍（建议）**：

1. **要合进 main 的主干** = **m30of**（同时带上 L1+L2）。  
2. **不必再合** fqzoo、network（与 fqzoo 重复；network 只是本地换名提交）。  
3. **默认不合** mw2rn；若你事后发现聚类/打开条目行为缺了，再单独 `git diff main mw2rn -- list_cluster.rs open_entries.rs` 挑拣。

## 3. 推荐合并路径（方案 A 已于 2026-08-02 执行）

> 前提：工作区先弄干净（commit / stash）；私有仓若要 PR，Cursor GitHub App 已授权。

### 方案 A（推荐）：只合 m30of → main

```bash
cd E:\Code\CursorConfigManagerTauri2
git status                    # 必须干净
git checkout main
git pull --ff-only origin main   # 若远端已超前；冲突则先处理
git merge cursor/cloud-agent-1785631288728-m30of -m "merge: cloud m30of (network N1-N4+P2 + Plan/05 snapshot)"
# 编译验收
npm run verify:tauri
cargo test --manifest-path src-tauri/Cargo.toml --lib
# 满意后再 push / 开 PR
```

合并后可删冗余分支（远程需 `git push origin --delete <名>`）：

| 分支 | 删？ |
|---|---|
| fqzoo | 可删（已被 m30of 覆盖） |
| network | 可删本地（未 push 则只 `git branch -d`） |
| mw2rn | 可删（除非你要挖 L3） |
| m30of | main 合入并 push 后可删 |

### 方案 B：先合 network，再合 m30of

仅当你想保留「网络库单独 commit 历史」叙事时：

```bash
git checkout main
git merge cursor/network-library-n1-n4-p2 -m "merge: network N1-N4 shelf"
git merge cursor/cloud-agent-1785631288728-m30of -m "merge: Plan/05 cloud snapshot"
```

注意：两支同父，第二次 merge 仍可能大量改同一文件——与直接合 m30of 结果应接近，但历史多一个节点。

### 方案 C：不合代码，只归档

若 main 已用别的方式收齐功能：把本文件留作考古；远程 `cloud-agent-*` 标删除即可。

## 4. 合并前自检清单

1. `git status` 干净？当前若在 `network` 上还有未提交证据文档，先处理。  
2. 是否接受 **丢掉 mw2rn 的 list_cluster/open_entries**？不接受 → 先 diff 再决定。  
3. m30of 含 `ccm` CLI / 包号 `0.2.0` 等——合并后跑一遍 `tauri:build` 或至少 `cargo test --lib`。  
4. 私有仓：push/PR 前确认 GitHub OAuth（见 Learning/06）。

## 5. 和「只是尝试用云」的对应关系

| 你的动作（推断） | 留下的支 |
|---|---|
| 云尝试 1 | mw2rn |
| 云尝试 2（网络库较完整） | fqzoo |
| 本地把暂存网络库收成正式 commit | network（≡ fqzoo） |
| 云尝试 3（Plan/05 大包） | m30of |

因此「合并他们」在工程上等于：**把最后一次云快照（m30of）收进 main，其余当重复试验清理掉**——不是把四条支两两乱合。
