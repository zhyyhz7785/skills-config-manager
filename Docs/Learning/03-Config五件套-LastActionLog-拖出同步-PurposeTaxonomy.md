## 2. Config 五件套

**结论**：这是旧「用户级 Cursor 目录 ↔ 备份根」开关，不是永久库 Deploy/Withdraw（是什么：放入容器生效 / 移出或存回库；起什么作用：管「库正本」与「工具正在读的位置」）。本仓保持空操作是正确取舍。

**前提**：产品已改以永久库台账为主；主仓 UI 已无此入口。

**机制（原理）**：禁用 → 文件挪到备份侧；启用 → 搬回原路径。五方法只是「改目录模式 / 单开单关 / 全开全关 / 刷新树」。

**边界**：**建议**不再实现真实启停服务，否则与库路径模型双源真相。

---

## 3. LastActionLog 与「完整审计」

**结论**：「完整审计」在本产品 = 可变操作尽量经同一入口记一条短摘要，不是不可篡改的完整 diff（是什么：文件差异对照；起什么作用：看改了哪些行）流水。

**前提**：容量环形约 50 条（新进旧出）；只读操作通常不记。

**机制**：写成功 → 头插一条（时间、方法名、人读摘要）→ 截断保存。

**边界**：本仓类型仍在、写回未接（**已验证**）。对齐主仓：**建议**统一写入口；落地效果 **待验证**。

---

## 4. 拖出同步性

**结论**：操作系统原生拖文件必须在「拖开始」同一拍同步发起；异步会丢拖势，表现为拖出去没有文件。

**前提**：同一次拖动常有两条信息——可读路径文案（应用内定级）+ 真实本地文件（给外部程序）。路径须由本机按条目解析，渲染侧不得伪造任意路径；网络盘路径宜跳过（易崩）。

**机制**：同步链 = 拖开始 → 立刻交出已解析的本地路径。本仓已能解析路径，但发起仍走异步（**已验证**读码）→ 相对主仓仍是缺口。

**边界**：**建议**改为同步发起，失败则静默只留文案通道。效果 **待验证**。

---

## 5. PurposeTaxonomy 大启发式

**结论**：词表管「用途叫什么」；大启发式用 id/备注等元数据关键词猜用途，减少手填。它**不能**回答「这条对多少项目成立」（那是层级原则的事）。

**前提**：工作面隔离——软件不读正文做学科判定，只读台账元数据。主仓层级现行：项目来源→L2；用户级规则→L0；其余未分类（L1 多靠人拖）。

**机制**：更具体的关键词优先；泛词靠后，避免乱贴。用途与层级正交：猜错用途可改；层级宜少自动、多人工。

**边界**：本仓 MVP 按资产种类给默认层级/用途，与主仓策略不一致（**已验证**）。要对齐体验再迁大词表（**建议**）；否则标明「启发式非担保」。

---

## 6. 关系与改码边界

```text
旧 Config 启停  ≠  库台账 Deploy/Withdraw
写操作摘要     ≠  完整 diff 审计
拖出同步发起   ≠  应用内定级拖拽（可并存）
用途启发式     ≠  L0/L1/L2 准入
```

修拖出同步不必动 Config；补日志不必扩词表。
