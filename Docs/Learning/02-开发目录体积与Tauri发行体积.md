# 开发目录很大 ≠ Tauri 发行很小

> 回答：「为什么 `CursorConfigManagerTauri2` 文件夹这么大？不是说 Tauri 2 体积很小吗？」  
> 对照：[04-启动与测试](../04-启动与测试.md) 发行口径；产品壳选型见 [01-核心逻辑](../01-核心逻辑.md)。

## 1. 结论

**已验证（本机 2026-07-30）**：本仓工作区约 **12.3 GB**，几乎全是**开发产物**，不是「用户拿到的 exe」。

| 口径 | 量的是什么 | 本仓数量级 |
|------|------------|------------|
| **工作区 / 文件夹** | 源码 + 依赖缓存 + 编译中间物 | ≈12.3 GB |
| **发行物（用户安装包/exe）** | 最终可运行程序 | 闸门纯 Rust ≈**5.68 MB**（04·P3）；迁移过渡另议 |

Tauri 宣传的「小」专指**发行物**：壳薄、不内嵌整份 Chromium，靠系统 **WebView2**（是什么：Windows 自带的嵌入式浏览器控件；起什么作用：渲染 UI，体积算在系统里而不进你的 exe）。  
它**从不承诺** `src-tauri/target` 与 `node_modules` 会小——那是给编译器与包管理器用的工地。

口诀：**工地可以很大；交付物才谈瘦。**

## 2. 本仓空间拆解（已验证）

| 路径 | 约占用 | 是什么 | 起什么作用 | 会进 Git / 进 exe 吗 |
|------|--------|--------|------------|---------------------|
| `src-tauri/target/` | **≈11.5 GB** | Rust **cargo**（是什么：Rust 的包管理与构建工具；起什么作用：编译依赖与本项目）的输出目录 | 存放 debug/release 目标文件、增量编译缓存 | **否**（`.gitignore` 已忽略）/ 否 |
| └ `target/debug/` | ≈9.9 GB | 调试构建产物（符号多、未优化、增量碎片多） | `tauri:dev`、`cargo test` 日常编译 | 否 |
| └ `target/release/` | ≈1.6 GB | 发行向构建的中间与成品缓存 | `tauri:build` 优化编译 | 否（成品另拷出） |
| `node_modules/` | ≈785 MB | npm 依赖树 | 跑 Vite、脚本、可选 Electron/sidecar 工具链 | **否** / 否 |
| 源码 + Docs + 配置等 | ≪10 MB 量级 | 真正「项目内容」 | 人写的代码与文档 | 是 / 经构建进包 |

**推断**：再开多次 `tauri:dev` / 换 toolchain / 清不干净的增量，debug 仍可能继续涨；删 `target` 后下次编译会重建（时间换空间）。

## 3. 为什么容易把两件事混在一起

结论：口语里的「Tauri 很小」缺主语；主语一换，数量级差三个数量级以上。

```text
听说「Tauri 很小」
        │
        ├─► 以为：整个项目文件夹应该只有几 MB     ← 错口径
        └─► 实际指：发给用户的程序通常远小于 Electron 发行包  ← 对口径
```

| 对比项 | Electron 常见印象 | Tauri 常见印象 | 本仓要额外记住 |
|--------|-------------------|----------------|----------------|
| 发行 exe/安装包 | 往往几十～上百 MB（内嵌 Chromium） | 常可到个位数～十几 MB 级（用系统 WebView） | 迁移期若**打入 Node sidecar**，过渡包会变胖，**勿与闸门 5.68 MB 混比**（**已验证**·04） |
| 开发目录 | `node_modules` 已很大 | 再加 `target/`，往往 **更大** | Rust 编译缓存是主因 |
| 运行时依赖 | 自带浏览器引擎 | 依赖本机已装 WebView2 | 用户机缺运行库时要另装，不进「文件夹很大」叙事 |

## 4. 关键概念（读体积时用）

| 概念 | 是什么 | 起什么作用 |
|------|--------|------------|
| **工作区体积** | 磁盘上仓库目录总字节 | 影响本机磁盘与备份；与「产品瘦不瘦」无关 |
| **发行体积** | 用户安装或便携运行所需文件总大小 | 下载、拷贝、宣传口径的正确对象 |
| **编译产物 / artifact** | 源码经编译器生成的 `.rlib`、`.exe`、增量文件等 | 加速下次编译；可删可重建 |
| **依赖缓存** | `node_modules`、Cargo registry/git 缓存（常在用户目录）等 | 避免每次从网络重下；仓库内主要见 `node_modules` 与 `target` |
| **Debug vs Release** | 调试构建 vs 优化构建 | Debug 快迭代、体积与符号膨胀；Release 慢编、产物更适合分发 |
| **WebView2 外置** | UI 引擎不打进你的二进制 | exe 变小的主因；代价是依赖系统组件 |
| **Sidecar / 过渡发行** | 迁移期可能附带的 Node 运行时与业务进程 | 功能完整优先时体积回升；与「纯 Rust 闸门」不是同一产品形态 |

## 5. 若只想「文件夹变小」可以做什么

结论：清的是**可重建缓存**，不是删业务源码。下列为常见做法；是否执行由你决定（**建议**，未在本次代清）。

| 动作 | 效果 | 代价 |
|------|------|------|
| 删除 `src-tauri/target/` | 立刻掉约 **11+ GB** | 下次 `tauri:dev` / `build` / `cargo test` 全量重编，耗时长 |
| 删除 `node_modules/` 后 `npm install` | 掉约 **0.8 GB** 再装回相近大小 | 重装依赖时间；体积通常回到同量级 |
| 少用并行多 profile、少留废弃 toolchain | 减缓 `target` 膨胀 | 需自己约束开发习惯 |
| 不要指望「换成 Tauri 源码目录就变几 MB」 | — | 源码本就小；大的从来是工地 |

**待验证**：清 `target` 后本机一次冷编译实际分钟数（视 CPU/磁盘浮动，04 未给本机实测）。

## 6. 记忆链

```text
文件夹 12GB  →  几乎全是 target(debug) + node_modules
Tauri「很小」→  指发行 exe（闸门≈5.68MB），不是指开发目录
Electron 对比 →  比的是用户包，不是比谁的 node_modules/target 更瘦
迁移仓额外 →  过渡若含 Node，宣传勿说「纯 Tauri 全量且极瘦」
```
