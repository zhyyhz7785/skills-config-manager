# 核心逻辑

> 面向人类读者：产品在干什么、为难谁、用什么办法、边界在哪。  
> 模块与路径见 [02-项目架构](02-项目架构.md)。调研/计划/测评长文在私有笔记仓，不随本仓公开。

## 1. 一句话

CursorConfigManager（CCM，本机配置资产管理器）把多工具、多项目里散落的 skills / rules 等配置，收到本机**永久库**统一记账；需要生效时再放到工具真正读取的**容器**目录。开源获取先进入**网络库**只读橱窗，用户确认后再晋升永久库。库里的文件不生效，容器里的才生效。

**本仓**：自 **2026-07-31** 起为 CCM **开发与交付主力**（纯 Tauri 2 + Rust）。安装包显示名仍为 CCM-Tauri2，数据目录 `%APPDATA%\CCM-Tauri2`。

## 2. 解决什么困难

| 困难 | 表现 |
|------|------|
| 散落 | 同一套规则出现在用户级 / 多项目容器里，不知道权威副本在哪 |
| 同名多版本失控 | 同名文件多份改稿，分不清哪份是定稿 |
| 难复用 / 难对账 | 靠手工复制与记忆；缺少台账 |
| 生效位置不直观 | 「备份里有」≠「Cursor 能读到」 |
| 开源获取易污染定稿 | 直接把远端技能装进生效目录，难回滚、难人选 |

「版本」这里指**磁盘上内容不同的同名副本**，不是 Git 完整版本历史。

**本软件不解决**：如何写好一条 skill / rule（内容工作面，见 §5）；不做 Git 式提交树；不做中央市场/云账号。

## 3. 什么样的用户需要

| 适合 | 不太需要 |
|------|----------|
| 长期维护多套 Cursor / Claude / Codex 配置的个人开发者 | 单项目、从不动配置的人 |
| 需要「停用仓库 + 按需放入容器」 | 把管理器当内容编辑器或 Git 替代品的人 |
| 需要从开源仓安全试看再定稿 | 只要一键装到多 Agent 市场的人 |

## 4. 用什么机制（不展开实现）

| 概念 | 是什么 | 起什么作用 |
|------|--------|------------|
| **永久库** | 本机内容权威根（默认 `C:\CursorSkills`；用户可改） | 停用仓库与台账所在；在此不生效 |
| **网络库 / 网络容器** | 与永久库隔离的只读开源缓存根（默认 `{永久库}\net`，如 `C:\CursorSkills\net`；改永久库目录时随之调整） | 拉取/检查更新开源 skills/rules；不可编辑、不可直部署到活动容器 |
| **上次稳定库根** | 设置里记住的最近一次**非临时目录**永久库路径 | 若库根被指到系统 Temp，启动时优先收回此处，避免丢台账 |
| **全局工作区** | 用户级 Agent/工具槽位（Cursor / Claude / Codex） | 导航可见多选；每区绑独立容器根；默认 Cursor；侧栏分组标题显示为「工作区」 |
| **焦点工作区** | 侧栏当前高亮的工作区 | 部署 / 撤回 / 刷新默认写入该区容器 |
| **活动容器** | 主表顶栏路径：当前焦点工作区下、工具实际读取的目录（如 `~\.cursor`、项目 `.cursor`） | 部署后配置才对工具生效；勿与网络容器混淆 |
| **网络侧栏「容器」** | 网络货架侧栏分组名（原「热门仓库」）；下列为精选/用户钉的开源源 | 选源、显隐、拉取进网络容器缓存；不是活动容器 |
| **侧栏工作区 / 容器区** | 本地货架两组导航（标题「工作区」「容器」） | 单行眼睛显隐；标题三钮＝全开眼 / 全关眼 / 齿轮池；关眼进池；扫描默认项目全开眼 |
| **网络中间表** | 点左侧「网络」后上部的浏览表（默认开眼源已索引 skill） | 开眼源＝侧栏眼睛打开、社区还须在候选池（社区段前 N 个可点的仓）内；未点源＝开眼源并集；点源再收窄；关眼立即从表消失（不删索引/缓存）；不走人群短语门槛；与下部永久库同一套行外观，但**不**画 L0/L1/L2（库存浏览层级）/ **未分类**（还没写入这三档的那一组）分组头；级别列对网络行只显示「未分类」。切走再切回不丢已铺的**漏斗池**（当前筛选用的条目数组） |
| **筛选货架** | 左侧第三态（本地 / 网络 / 筛选） | 用人群档+短语收窄后再挑货；点源只在网络货架做，选源仍收窄筛选池 |
| **筛选中间表** | 点「筛选」后上部的匹配表 | 与网络中间表同一套行、同样不画 L0 分组头；左侧芯片收窄后挑货；点人群档后**表立刻出**，**功能芯片**（按路径/域把剩余列表切成互斥钮）可稍后填；网行须先转入永久库才能部署 |
| **人群档 / 短语** | 按名称+摘要派生的九档画像（界面「产品」对应词表「产品经营」档——需求、决策、经营）及短意图词（现场计算，不写盘；一行可挂多个短语）。档内还有**细子档**（认哪块活的第二层芯片）。软件条数远大于一屏时，人群行在「软件」旁先亮少数**切片**（自动化抓取 / 应用实现 / 质量安全 / 云数据交付），点切片才继续细子档，不铺两千行 | 把列表收到可扫的规模；未匹配进「未归类」；芯片在筛选左侧两列等宽；空芯片不亮；当前层 ≤12 跳过下一层 |
| **台账** `catalog.json` | 永久库根下的元数据总账 | 记路径、哈希、部署状态等（SSOT） |
| **网络索引** `network-index.json` | 网络容器根下的独立索引 | 记来源 URL、指纹、缓存相对路径；与永久库台账隔离 |
| **应用设置** `ccm-settings.json` | 永久库根下（与台账同目录）；AppData 仅 `library-pointer.json` 记库路径 | 库根、网络钉选、工作区可见/默认、热门可见上限、UI 偏好；测试时可与台账一并回厂 |
| **Git HTTP 代理** | 进程环境变量或 Windows 系统代理（设置窗不再提供填写框）；注入 git/gh/curl 环境 | 公司网/防火墙下拉取开源仓 |
| **热门可见上限** | 侧栏热门主列表最多显示 N 条（其余进池/裁剪） | 控制货架密度，避免眼花 |
| **层级** | 台账条目的 L0 / L1 / L2 分类标签（未写或显式标成未分类则为未分类） | 中部：**本地上部与永久库**按这四组聚类，**网络与筛选扁平列出**（不画分组头）；只有永久库行能改级别。命令 / 右键 / 级别下拉 / 拖到分组效果相同：改标签、列表移位、**文件名**（列表里那一格，来自条目 id）按**来源**加档位前缀——本地（容器入库、自写、或网络件已被用户改过）用 `L0`/`L1`/`L2`（已有 `L1D10`/`L2P` 等**域缀**——同一档内再标学科或项目的前缀——且档位不变则保留）；未改过的网络晋升技能用 `S0`/`S1`/`S2`，网络规则用 `R0`/`R1`/`R2`；代理 / 命令 / 钩子仍是 `A`/`C`/`H`。未分类去掉档位前缀。各工作区容器里同名副本一并改名 |
| **用途** | 台账条目的用途标签（如通用、规范） | 扫描静默归类仍可写入；**不再**作为列表子分组 |
| **异步拉取进度** | 网络拉取作业发出的进度事件（含 git `--progress`） | 长克隆时可见进度、可取消 |
| **部署配方** | 一组条目 id + 目标工作区 id 的可复用清单 | 一次按清单布置，减少手勾 |
| **精选层** | 永久库内用户标记的地基子集（规划中） | 一键布置的默认勾选清单；不是第二权威根 |

**主流程**（用户视角）：

1. （可选）网络容器：基线/Git URL 拉取 → 只读浏览 → 检查更新确认后覆盖**缓存**  
2. **存入永久库**（复制；同名不同哈希走冲突窗）  
3. **扫描建库** / 迁入 → **相对台账的增量发现**：在**设置**里配置要扫的**工作区容器根**（各 Agent 用户级配置目录）与**项目扫描根**（`ProjectScanRoots`；空则扫盘符）；点工具栏扫描不再选目录，直接预览未登记项。同哈希缺回链则静默回链；**同名不同哈希跳过**（人选走刷新）。确认入库（有新登记 / 复制入库 / 新项目）后按默认逻辑静默写层级与用途；纯回链不写。复查走顶栏「自动归类」  
4. 在设置或侧栏眼睛勾选要显示的**全局工作区**（侧栏标题「工作区」；须同时在「工作区域」且开眼才出现）；点选焦点；可用标题「全开眼 / 全关眼」批量显隐；网络侧栏「容器」分组「全关眼」表示**明确全藏**，不会在下次单开一只眼时被默认回填成全开。点左侧「本地」时中间仍是原来的分区列表；点「网络」上部浏览开眼源的已索引 skill；点「筛选」左侧用人群短语收窄、中间只留匹配表（池同样只含开眼源）；点档后表先出、功能芯片可稍后；网行须先转入永久库才能部署（空意向进「未分类」，在永久库里再改级别）。转入并部署进当前容器后，下部同名行应变绿，上窗该行右键为撤回 / 打开条目目录  

5. **部署**：永久库 → 活动容器。焦点部署或「部署全部」（一次写入各可见工作区）。**默认工作区**＝**copy**（复制；库正本保留）；**非默认工作区**＝**symlink**（符号链接：容器路径指回库文件；跟随库改动；撤回 unlink）  
6. **移出 / 存回**：哈希同则删活动容器侧（symlink 则 unlink）；异则人选  
7. **刷新对账**（独占内容人选）：已登记范围内活动容器存活副本 ↔ 库正本；哈希不同弹冲突窗；**不**静默软登记新文件；指向库的 symlink 不当作假冲突

### Cursor Rule 生效边界（**已验证** 对齐 Electron 实测）

| 落点 | 是什么 / 起什么作用 | CCM 是否写入 |
|------|---------------------|--------------|
| **Project Rules** | 项目 `{仓}\.cursor\rules\{id}\{id}.mdc`（**文件夹壳**；Agent 可读 `**/*.mdc`） | 导航选项目后**部署**即可 |
| `~\.cursor\rules\{id}\{id}.mdc` | 用户级磁盘上的 rule；CCM 可管理/对账 | 可部署，但 **≠** 全局生效 |
| **User Rules** | Cursor Settings → Rules（Customize → Rules）纯文本；跨项目进 Agent | **不写**；须用户复制正文 |

口诀：**项目部署进项目 `.cursor/rules`；跨项目须粘贴进 Settings → Rules。**  
**本仓落盘约定**（skill=`skills/{id}/`；rule=文件夹壳）：仅约束本仓库 CCM 产品；不成可复用 Skill，无跨项目复用价值（`.cursor/rules/L1-ccm-library-layout`）。

## 5. 边界

### 工作面隔离

| 工作面 | 可以想什么 | 禁止想什么 |
|--------|------------|------------|
| A. 写 skills / rules | 领域约束与 AI 行为 | 管理器 IPC / 服务实现 |
| B. 写本仓代码 | 路径、台账、Deploy/Withdraw、壳 | 正文语义分支 |

一句话：**编内容时当管理器不存在；写代码时正文是不透明字节。**

### 本仓额外边界

- **网络库硬边界**：不可编辑、不可回灌、不可直部署容器；永久库永不被网络静默改写。  
- **全局工作区**：可见多选、容器根可改；侧栏标题「工作区」；项目侧多工具容器仍属 Should。  
- **侧栏显隐**：工作区全关须保留至少一个（默认槽）；容器允许全部关眼进隐藏池；工作区须 `InWorkArea`（在工作区域）且在可见 id 列表，二者缺一则侧栏完全看不到（含 Codex 等）。  
- **永久库路径**：勿与旧 Electron CCM 长期共写同一 `%APPDATA%\CCM-Tauri2\settings.json` 却指向不同 Temp 库；非 Temp 用户路径不应被默认 Spike 覆盖。  

- **布置语义**：默认槽禁止 symlink「库＝生效」；非默认槽 symlink 失败禁止静默改 copy。  
- **Cursor User Rules**：CCM **不**逆向写入 Settings；`~\.cursor/rules` 部署成功 ≠ 跨项目全局加载。  
- **界面语言**：默认简体中文；设置可切英文。选择存在浏览器 **localStorage**（网页本地键值存储）键 `ccm.locale`（**locale**＝语言区域码，用来选定哪本界面词典）。不跟系统/浏览器语言。Rust / CLI 报错与 Milkdown/Crepe 内核工具条仍单语中文。  
- **暂缓**：列表「曾用于」分区已移除（复杂度高、收益低）；功能稳定性开发完毕后可评估恢复。  
- **未过闸门不得宣称「Tauri 可替代 CCM」**。

## 6. 记忆链 / 口诀

```text
谁痛（散落+同名多版）→ 给谁（多工具多项目个人）→ 办法（网络=检疫；库=定稿；容器=生效；哈希人选）
  → 本仓（**Tauri 2 开发主力**，2026-07-31）
```

1. **库 ≠ 生效**（默认槽靠 copy；非默认同 symlink 仍认库为正本）  
2. **同名 ≠ 同版**（看哈希）  
3. **网络库 ≠ 定稿**（须晋升）  
4. **扫描只登记不人选；人选只走刷新**  
5. **有记录且无变化 = 扫描看不见**（只看增量）  
6. **内容面 ≠ 软件面**  
7. **数据目录默认隔离**（`%APPDATA%\CCM-Tauri2`；可按需改库根）  
8. **能跑 ≠ 对比完成**（冷启/扫描秒表见 [04](04-启动与测试.md)）  
9. **`~\.cursor/rules` ≠ Settings User Rules**（跨项目须复制到设置）  
10. **一键布置 ≠ 丢细控**（部署全部/配方与分条部署同语义不同力度；精选层规划中）  
11. **侧栏「工作区」≠ 设置页「全局工作区」长名**（同一概念；侧栏用短标题）  
12. **扫描建库 ≠ 只扫用户级容器**（还要登记项目扫描根下的项目容器）  
13. **全关眼 ≠ 未配置**（热门 pin 空列表在已初始化后保持空，不回填默认全开）  
14. **AppData pointer ≠ 全量设置**（主体在库内 `ccm-settings.json`）  
15. **点目录 ≠ 一律跳过**（发现黑名单；`.github`/`.curated` 须下钻）
16. **扫描确认 ≠ 等人选归类**（有新项则静默写默认层级/用途；复查走顶栏「自动归类」）
17. **货架换表，熟词筛意图**（本地/网络/筛选三货架上部与下部永久库同一套列表行：容器 · **种类**（技能/规则等）· 文件名，上部另附分类/来源/层级浅色字；筛选左侧漏斗；网行须转入才能部署）
18. **界面中文 ≠ 跟系统语言**（默认 zh-CN；设置切 en；重启保持）
19. **设层级 ≠ 只改标签**（文件名按来源加档位前缀：本地 `L*`，未改过的网络技能 `S*` / 规则 `R*`；容器里同名项一起改）
20. **切货架 ≠ 丢漏斗池；点档 ≠ 等功能桶扫完**（表先出，芯片可稍后）
