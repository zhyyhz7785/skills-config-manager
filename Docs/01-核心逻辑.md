## 1. 一句话

CursorConfigManager（CCM，本机配置资产管理器）把多工具、多项目里散落的 skills / rules 等配置，收到本机**永久库**统一记账；需要生效时再放到工具真正读取的**容器**目录。开源获取先进入**网络库**只读橱窗，用户确认后再晋升永久库。库里的文件不生效，容器里的才生效。

**本仓（CursorConfigManagerTauri2）**：自 **2026-07-31** 起为 CCM **开发与交付主力**（纯 Tauri 2 + Rust）。Electron / Wails2 分别为维护线与壳实验线。

## 2. 解决什么困难

| 困难 | 表现 |
|------|------|
| 散落 | 同一套规则出现在用户级 / 多项目容器里，不知道权威副本在哪 |
| 同名多版本失控 | 同名文件多份改稿，分不清哪份是定稿 |
| 难复用 / 难对账 | 靠手工复制与记忆；缺少台账 |
| 生效位置不直观 | 「备份里有」≠「Cursor 能读到」 |
| 开源获取易污染定稿 | 直接把远端技能装进生效目录，难回滚、难人选 |

「版本」这里指**磁盘上内容不同的同名副本**，不是 Git 完整版本历史。

**本软件不解决**：如何写好一条 skill / rule（内容工作面，见 §5）；不做 Git 式提交树；不做中央市场/云账号。

## 3. 什么样的用户需要

| 适合 | 不太需要 |
|------|----------|
| 长期维护多套 Cursor / Claude / Codex 配置的个人开发者 | 单项目、从不动配置的人 |
| 需要「停用仓库 + 按需放入容器」 | 把管理器当内容编辑器或 Git 替代品的人 |
| 需要从开源仓安全试看再定稿 | 只要一键装到多 Agent 市场的人 |

## 4. 用什么机制（不展开实现）

| 概念 | 是什么 | 起什么作用 |
|------|--------|------------|
| **网络库** | 本机独立根目录上的只读缓存（开源橱窗） | 拉取/检查更新开源 skills/rules；不可编辑、不可直部署容器 |
| **永久库** | 本机根目录（默认可为 `C:\CursorSkills`；对比期姊妹仓须用**独立**库根） | 停用仓库与内容权威源；在此不生效 |
| **全局工作区** | 用户级 Agent/工具槽位（Cursor / Claude / Codex） | 导航可见多选；每区绑独立容器根；默认 Cursor |
| **焦点工作区** | 侧栏当前高亮的工作区 | 部署 / 撤回 / 刷新默认写入该区容器 |
| **容器** | 各 AI 工具约定读取目录（如 `~\.cursor`、项目 `.cursor`） | 放在这里才对工具生效；列表可并列多段「容器中 · {名}」 |
| **台账** `catalog.json` | 永久库根下的元数据总账 | 记路径、哈希、部署状态等（SSOT） |
| **网络索引** `network-index.json` | 网络库根下的独立索引 | 记来源 URL、指纹、缓存相对路径；与永久库台账隔离 |
| **应用设置** | 独立 AppData 目录下的 settings | 库根、工作区可见/默认、UI 偏好；不替代台账 |

**主流程**（用户视角）：

1. （可选）网络库：基线/Git URL 拉取 → 只读浏览 → 检查更新确认后覆盖**缓存**  
2. **存入永久库**（复制；同名不同哈希走冲突窗）  
3. 扫描建库 / 迁入 → 登记资产到台账  
4. 在设置中勾选要显示的**全局工作区**；侧栏点选焦点  
5. **部署**：库 → **焦点工作区**容器（复制，库正本保留）  
6. **移出 / 存回**：哈希同则删容器侧；异则人选  
7. **刷新对账**：容器存活副本 ↔ 库正本

细目录边界与 Cursor Rule 生效层级：见归档 [01-核心逻辑](Archive/legacy-ccm-electron-2026-07-29/01-核心逻辑.md)（原 Electron 实测）；本仓换壳后须复测再标已验证。

## 5. 边界

### 工作面隔离

| 工作面 | 可以想什么 | 禁止想什么 |
|--------|------------|------------|
| A. 写 skills / rules | 领域约束与 AI 行为 | 管理器 IPC / 服务实现 |
| B. 写本仓代码 | 路径、台账、Deploy/Withdraw、壳 | 正文语义分支 |

一句话：**编内容时当管理器不存在；写代码时正文是不透明字节。**

### 本仓额外边界

- **主仓 Electron 继续自用**：本仓失败不得停更主仓发行。  
- **对比期必须数据隔离**：不同产品名 / AppData / 永久库根（见 Plan/01）。  
- **网络库硬边界**：不可编辑、不可回灌、不可直部署容器；永久库永不被网络静默改写。  
- **全局工作区**：可见多选、容器根可改；项目侧多工具容器仍属 Should（见 Plan/04）。  
- **未过闸门不得宣称「Tauri 可替代 CCM」**。

## 6. 记忆链 / 口诀

```text
谁痛（散落+同名多版）→ 给谁（多工具多项目个人）→ 办法（网络=检疫；库=定稿；容器=生效；哈希人选）
  → 本仓（**Tauri2 开发主力**，2026-07-31）· Electron 维护 · Wails 实验
```

1. **库 ≠ 生效**  
2. **同名 ≠ 同版**（看哈希）  
3. **网络库 ≠ 定稿**（须晋升）  
4. **内容面 ≠ 软件面**  
5. **姊妹仓数据默认隔离**（CCM-Tauri2 AppData；可按需改库根）  
6. **能跑 ≠ 对比完成**（度量见 Evaluations）
