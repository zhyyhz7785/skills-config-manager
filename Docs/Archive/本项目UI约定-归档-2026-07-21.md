# 本项目 UI 约定

CursorConfigManager 的桌面壳：**Electron 42.5 + React + Vite + TypeScript**。  
业务逻辑在主进程（`electron/services`），界面在渲染进程（`src/`），经 `preload` / IPC 通信。

**外观**：浅色主题（Fluent Light 观感）；**无边框窗口**，系统标题栏/菜单栏已去掉；最小化/最大化/关闭嵌在首行工具栏右侧（与 Cursor 类似），工具栏空白处可拖动窗口。

**交互**：顶栏仅保留「扫描迁入 / 设置永久库 / 刷新」；放入、移出、标签、项目排序等走**右键菜单**。三栏之间可拖分割线，宽度写入 settings。未配置永久库时默认 `C:\CursorSkills`，启动后弹出扫描迁入预览。

## 已落地要点

| 位置 | 约定 |
|------|------|
| `electron/main.ts` | 窗口创建、注册 `ccm:invoke` |
| `electron/preload.ts` | `contextBridge` 暴露 `window.ccm.invoke` |
| `electron/appController.ts` | 快照构建与全部命令面 |
| `src/App.tsx` | 单页：导航 / 库列表四区 / 详情 / 工具栏 / Dialog |
| `shared/ipc.ts` | IPC 方法名与 `AppSnapshot` 契约（对齐原 `Host/Dtos.cs`） |

辅助流（添加项目、扫描迁入、扫描项目、标签编辑）使用 React 模态框，不另开系统窗口。

## 目录

```
electron/          # 主进程 + services
src/               # React UI
shared/            # 类型与 IPC 契约
legacy-wpf/        # 旧 C# 对照（勿再作为构建目标）
Docs/              # 本文档
```

## 新增界面检查清单

1. 是否只通过 `window.ccm.invoke` 调主进程（渲染进程不直连 `fs`）？
2. 命令成功后是否刷新 / 使用返回的 `snapshot`？
3. 是否与现有工具栏 / 列表分区语义一致（容器中 / 曾用 / 永久库 / 缺失）？
4. settings 字段是否保持 PascalCase，catalog 是否保持 camelCase？

## 不要做的事

- 在渲染进程直接读写磁盘或改 catalog
- 把 hymd-code 的 `.build/electron` 定制壳拷来当运行时
- 再引入 WPF / WebView2 第二套壳（本仓已迁 Electron）
- 文档与实现脱节：改 IPC 契约时同步更新 `shared/ipc.ts` 与本文
