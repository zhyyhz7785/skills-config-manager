## 1. 启动前检查

### 1.1 环境

| 项 | 期望 |
|----|------|
| 工作目录 | `e:\Code\CursorConfigManager` |
| Node | 建议 **≥ 22.12**；本机若为 20.x，需确认 `node_modules\electron\dist\electron.exe` 已存在 |
| Electron | `package.json` 中 `"electron": "42.5.0"`；优先命中 `%LOCALAPPDATA%\electron\Cache` |

```powershell
cd e:\Code\CursorConfigManager
node -v
npm -v
Test-Path .\node_modules\electron\dist\electron.exe
Test-Path $env:LOCALAPPDATA\electron\Cache\*\electron-v42.5.0-win32-x64.zip
```

若 `electron.exe` 不存在且 Node &lt; 22：从 Cache 解压 zip 到 `node_modules\electron\dist\`，并把 `electron.exe` 绝对路径写入 `node_modules\electron\path.txt`。

### 1.2 数据（勿随意删）

| 路径 | 作用 |
|------|------|
| `%APPDATA%\CursorConfigManager\settings.json` | 应用设置（PascalCase；含永久库根、项目列表） |
| `{SkillsLibraryRoot}\catalog.json` | 永久库台账（camelCase） |
| `%USERPROFILE%\.cursor\` | 用户级容器 |

测试前建议备份：

```powershell
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
Copy-Item "$env:APPDATA\CursorConfigManager\settings.json" "$env:APPDATA\CursorConfigManager\settings.json.bak-$stamp"
# 将下面路径换成 settings 里的 SkillsLibraryRoot
Copy-Item "E:\cursor\CursorSkills\catalog.json" "E:\cursor\CursorSkills\catalog.json.bak-$stamp"
```

### 1.3 启动方式

**开发（热更新）：**

```powershell
cd e:\Code\CursorConfigManager
npm run dev
```

**已构建产物：**

```powershell
npm run build
npm start
```

窗口标题应为 `Cursor Config Manager`。底栏出现状态文案（永久库根 / catalog 条数等）即主进程已通。

## 2. 冒烟清单（建议顺序）

每步通过标准：界面有反馈（toast / 状态栏变化），且对应磁盘状态符合预期。

### A. 启动与快照

| # | 操作 | 期望 |
|---|------|------|
| A1 | 启动应用 | 无白屏；导航可见「用户级 (.cursor)」与项目树 |
| A2 | 看底栏 | 显示永久库根；`catalog N` 与备份的 entries 数接近 |
| A3 | 点「刷新」 | 列表重算，不报错 |

### B. 永久库目录

| # | 操作 | 期望 |
|---|------|------|
| B1 | 「设置永久库目录」→ 选**当前已有库**（勿另选空目录，除非刻意迁库） | 状态栏更新；`settings.json` 中 `SkillsLibraryRoot` / `LibraryRootConfigured` 正确 |
| B2 | 取消对话框 | 不改 settings |

### C. 导航与筛选

| # | 操作 | 期望 |
|---|------|------|
| C1 | 点「用户级」 | 活动容器为 `%USERPROFILE%\.cursor`；四区列表按用户级刷新 |
| C2 | 点某个已登记项目 | 活动容器为 `{项目}\.cursor` |
| C3 | 勾选/取消「技能/规则/…」筛选 | 列表条目种类变化 |
| C4 | 切换「域筛选」「聚类」 | 永久库余量区分组变化，不崩溃 |

### D. 选择与详情

| # | 操作 | 期望 |
|---|------|------|
| D1 | 单击一条库条目 | 右侧摘要显示 Id / 范围 / 路径等 |
| D2 | Ctrl+单击多选 | 选择摘要变为「已选 N 项」 |
| D3 | 切到 Markdown / 原文 | 有元数据文件时能看到内容 |
| D4 | 「原目录」「当前位置」 | 资源管理器打开对应文件夹 |

### E. 扫描迁入（只读预览 → 再确认）

| # | 操作 | 期望 |
|---|------|------|
| E1 | 「扫描迁入」 | 弹出预览；列出发现项（可含 needsAttention） |
| E2 | 取消 | 不改 catalog、不 Move 文件 |
| E3 | 仅勾选**明确要入库**的项 →「确认迁入」 | toast 显示新增/追加/跳过；源路径被 Move 进永久库对应 `skills|rules|…`；catalog 增加或更新条目 |
| E4 | 再扫一次同内容 | 同 hash 应倾向「追加来源 / 待收回」，避免无故复制出 `*-2` |

### F. 放入 / 移出

| # | 操作 | 期望 |
|---|------|------|
| F1 | 选中**在库**条目 →「放入」 | 文件出现在当前容器约定路径；条目进「容器中」；`isInLibrary=false` |
| F2 | 选中**容器中**条目 →「移出」 | 文件回到永久库；条目离开「容器中」 |
| F3 | 单一真相 | 同一内容不应同时在库路径与容器路径各留一份 |

### G. 标签与范围

| # | 操作 | 期望 |
|---|------|------|
| G1 | 单选 →「编辑标签」 | 可写 `global` 或 `project:{id}`，用途逗号分隔 |
| G2 | 「设为用户级」 | `tags.scope` → `global` |
| G3 | 在项目导航下「设为当前项目」 | `tags.scope` → `project:{当前项目Id}` |

### H. 项目台账

| # | 操作 | 期望 |
|---|------|------|
| H1 | 「添加项目」→ 浏览选根目录 | 导航出现新项目；settings `Projects` 增加 |
| H2 | 「编辑项目」/「置顶」/「删除项目」 | 列表与 settings 同步（删除前确认非误点） |
| H3 | 「扫描项目」→ 预览 → 只勾选新发现 → 确认 | 新项目入库；已登记项勿重复添加 |

### I. 缺失与恢复（谨慎）

| # | 操作 | 期望 |
|---|------|------|
| I1 | 若有「缺失」区 | 选中 →「清理缺失」仅删 catalog 记录，不恢复文件 |
| I2 | 「全部恢复」 | 按 InitialPath 尝试恢复；看 toast 计数；失败项读消息，勿强行覆盖 |

### J. 其它配置 Tab（启用/禁用）

| # | 操作 | 期望 |
|---|------|------|
| J1 | 右侧「其它配置」勾选切换 | 在 `%USERPROFILE%\.cursor` 与备份根（默认 `E:\cursorBf`，可在 settings `BackupRoot`）之间 Move |
| J2 | 「全部启用 / 全部禁用」 | 批量生效；测完建议恢复常用项为启用 |

## 3. 回归核对（测完必做）

```powershell
# 1) settings 仍是合法 JSON，关键字段在
Get-Content "$env:APPDATA\CursorConfigManager\settings.json" -Raw | ConvertFrom-Json |
  Select-Object SkillsLibraryRoot, LibraryRootConfigured, @{n='Projects';e={$_.Projects.Count}}

# 2) catalog 仍是合法 JSON
$root = (Get-Content "$env:APPDATA\CursorConfigManager\settings.json" -Raw | ConvertFrom-Json).SkillsLibraryRoot
$c = Get-Content (Join-Path $root "catalog.json") -Raw | ConvertFrom-Json
"entries=$($c.entries.Count) version=$($c.version)"
```

对比测试前备份：entries 数量变化应能对应你做过的迁入/去除/清理；若异常暴跌，用备份还原。

## 4. 已知边界（测试时别误判为缺陷）

1. **Move 不是 Copy**：放入/移出/迁入会搬走文件；不要用资源管理器同时改同一路径。  
2. **两套 JSON 命名**：settings = PascalCase；catalog = camelCase。  
3. **污染项**（如 `skills-cursor`、脚手架 `plugin-creator`/`launch`、`CLAUDE.md`/`AGENTS.md`）不会进永久库。  
4. **用户主目录 / `.cursor` 不能登记为项目**。  
5. **Electron 体积大**属选型取舍，与功能无关。  
6. Node 20 下 `npm install` 可能装不全 Electron 二进制——见 §1.1。
