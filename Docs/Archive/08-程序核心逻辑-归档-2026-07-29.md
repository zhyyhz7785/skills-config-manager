# 程序核心逻辑

> 面向「这个软件到底在干什么」：为难谁、给谁用、用什么办法、管到哪些目录。  
> 操作步骤见 [07-帮助文档](07-帮助文档.md)；模块与栈见 [01-项目架构](01-项目架构.md)；目录细则见 [Research/004](Research/004-目录录入映射-Cursor-Claude-Codex-2026-07-21.md)。  
> **编号说明**：根目录 `00` 已留给 [工作面隔离原则](00-工作面隔离原则.md)（硬约束先读），故本说明用 `08`。

## 1. 一句话

CursorConfigManager（CCM，本机配置资产管理器）把多工具、多项目里散落的 skills / rules 等配置，收到本机**永久库**统一记账；需要生效时再放到工具真正读取的**容器**目录。库里的文件不生效，容器里的才生效。

## 2. 解决什么困难（优化后的问题陈述）

用户真正卡的不是「会不会写 skill」，而是**资产生命周期失控**：

| 困难 | 表现 |
|------|------|
| 散落 | 同一套规则出现在用户级 `.cursor`、多个项目 `.cursor`、偶尔还有 `.claude` / `.agents`；不知道「权威副本」在哪 |
| **同名多版本失控** | 同一名称的文件被多次优化后，旧稿、半成品、定稿散落在多个目录；用户很难判断**哪一份才是最后优化结果** |
| 难复用 | 项目 A 调好的 skill，很难干净地挪到项目 B 或用户级，而不靠手工复制、改名、漏文件 |
| 难对账 | 改过哪份、还在不在、是否与另一份同内容，全靠记忆；没有台账 |
| 生效位置不直观 | AI 工具只认固定容器路径；「备份文件夹里有」不等于「Cursor 能读到」 |

「版本」在这里指的是：**同名资产在磁盘上多份内容不同的副本，分不清哪份是最新定稿**——不是 Git 那种完整版本控制系统（Version Control System，用提交历史管理源码变更的工具）。CCM 用**永久库作权威落点 + 内容哈希比对 + 冲突时展示两侧信息让用户选**，降低「多份同名、不知孰新」的认知负担；它**不**自动替你保留无限历史版本树。

**本软件不解决**：如何写一条好的 skill / rule（那是内容工作面，见 [00](00-工作面隔离原则.md)）；也不做 Git 式分支/提交历史。它解决「放哪、何时生效、如何收回、如何记账」，以及**存回库时识别同内容 / 异内容并让人选留哪一版**。

## 3. 什么样的用户需要

| 适合 | 不太需要 |
|------|----------|
| 个人开发者，长期维护多套 Cursor / Claude / Codex 配置 | 只用一个项目、从不挪配置的人 |
| 多项目共用同一批 skills / rules，又想按项目开关 | 只在云端或单一仓库内管配置、不碰本机用户级目录的人 |
| 同一配置反复改多轮，副本已散到多个目录、分不清哪份是定稿 | 每条配置只存在一个目录、从无副本混淆的人 |
| 希望本机有一个「停用仓库」，需要时再放入容器 | 把管理器当成内容编辑器、Git 替代品或 AI 领域专家系统的人（错位） |

服务对象在架构文档中的表述：**个人开发者，统一管理多项目 / 用户级配置资产。**

## 4. 用什么方式：永久库 + 容器 + 台账

### 4.1 两个空间

```text
永久库（停用仓库）                   容器（工具运行时读取）
┌─────────────────────────┐         ┌──────────────────────────┐
│ C:\CursorSkills（默认可改）│         │ 用户级：~\.cursor 等      │
│ skills/ rules/ agents/… │ ─复制放入▶│ 项目级：{项目}\.cursor 等  │
│ catalog.json（台账）      │ ◀─移出──│ 只有这里的文件会「生效」   │
└─────────────────────────┘         └──────────────────────────┘
```
| 概念 | 是什么 | 起什么作用 |
|------|--------|------------|
| **永久库** | 本机一个根目录；设置键 `SkillsLibraryRoot`，未配置时默认 `C:\CursorSkills` | 配置资产的停用仓库与内容权威源；在这里时**不会被** Cursor/Claude/Codex 调用 |
| **容器** | 各 AI 工具约定的读取目录（见 §5） | 文件放在这里才对工具「生效」 |
| **台账** `catalog.json` | 落在永久库根下的元数据总账 | 记每条资产的 id、类型、库内相对路径、是否在库、部署路径、来源、内容哈希、历史；项目列表也在此（SSOT，唯一权威数据源） |
| **应用设置** | `%APPDATA%\CursorConfigManager\settings.json` | 库根路径、扫描范围等偏好；不替代台账 |

界面与文档统一称「永久库」（即 `libraryRoot`）。勿与设置项 `BackupRoot`（可选旧备份扫描源，常见默认 `E:\cursorBf`）混淆。

### 4.2 管哪些资产类型

| kind | 含义 | 库内典型落点 |
|------|------|----------------|
| skill | 技能包 | `skills/{id}/`（含 `SKILL.md`） |
| rule | 规则 | `rules/…` |
| agent | 代理说明 | `agents/…` |
| command | 命令 | `commands/…` |
| hook | 钩子 | `hooks/…` 或 `hooks.json` |

### 4.3 用户视角主流程（机制，不展开实现）

1. **扫描建库**：发现本机用户级与各项目容器中的资产 → 写入台账（登记；不必然立刻搬文件）。
2. **迁入永久库**：把仍在容器侧、需要入库的文件**收进**永久库，并更新台账。
3. **放入（部署）**：从永久库**复制**到当前选中的容器（库正本保留），工具才能读到。
4. **移出 / 存回**：从容器收回永久库；若库内已有同内容副本，只删容器侧多余文件；内容冲突则弹窗展示哈希/大小/时间/预览，由用户选保留哪边。
5. **刷新对账**：核对容器存活副本与永久库正本；哈希不同则弹比对窗（保留库版 / 用容器盖库 / 另存 / 跳过）。

**已上线**：部署=复制、库常驻正本、存回哈希同删异选、刷新冲突决议。  
**已移除（2026-07-27）**：「恢复初始 / 状态点选路径」——能力由「放入 / 曾用于再放入 / 刷新」覆盖；台账可仍含历史 `checkpoints` 字段但不写入、无 UI。

### 4.4 对账与「哪份是定稿」靠什么

台账字段 + 磁盘是否存在 + **内容哈希**（SHA-256：内容相同则摘要相同）。用来判断「是不是同一份」「有没有改过」，而不是靠文件名相同就当同一版。

| 情况 | 软件怎么帮 |
|------|------------|
| 多处同名但**内容相同** | 哈希一致 → 可视为同一版；存回库时可去掉多余容器副本，只留库内权威份 |
| 多处同名但**内容不同** | 哈希不同 → 视为不同版本；冲突时展示路径、哈希、预览等，由用户选择保留哪一边（或另存） |
| 需要「最后优化」的单一落点 | 约定：**永久库里的那份是权威定稿**；容器里是当前生效的工作副本 |

文件名相同**不能**说明谁新；修改时间可作参考，但以哈希是否一致、以及你在冲突窗里选定的那份为准。

## 5. 默认边界：工具读哪里

路径均相对用户主目录 `%USERPROFILE%`（代码里 `os.homedir()`），或相对**已登记项目根**。下表为**默认扫描 / 放入**边界（已验证以当前代码为准；细表见 Research/004）。

### 5.1 用户级（「通用」）

| 工具 | 容器根（放入目标） | 默认会扫到的核心路径 | 备注 |
|------|-------------------|----------------------|------|
| Cursor | `%USERPROFILE%\.cursor` | `.cursor/skills`、`rules`、`agents`、`commands`、`hooks`（含 `hooks.json`） | 种类最全；**其中 `rules/*.mdc` 作「全局 Agent Rule」未必生效**，见 §5.4 |
| Claude | `%USERPROFILE%\.claude` | **仅** `.claude/skills` | 其它 Claude 子目录现状不扫 |
| Codex | `%USERPROFILE%\.codex` | `.codex/skills` **与** `%USERPROFILE%\.agents/skills` | 放入默认落 `.codex`；`.agents` 仍可被发现 |

### 5.2 项目级

| 路径 | 工具归属 | 说明 |
|------|----------|------|
| `{项目根}\.cursor\skills|rules|agents|commands|hooks` | Cursor | **当前项目导航下，放入/移出的活动容器根是 `.cursor`** |
| `{项目根}\.claude\skills` | Claude | 可扫描发现；项目级多工具容器切换尚未做全 |
| `{项目根}\.agents\skills` | Codex | 同上 |

项目从哪来：扫描发现含 `.cursor` 的目录（默认可扫全部可读盘符，深度默认 5；可用设置收窄），再登记到台账的项目列表。

### 5.3 明确不在日常边界内的

| 项 | 说明 |
|----|------|
| 永久库根自身 | 扫描时跳过，避免把库内文件再当「发现项」 |
| `skills-cursor`（用户级） | **不纳入管理**（避免动到 Cursor 内置/扩展技能区） |
| `BackupRoot`（如 `E:\cursorBf`） | 可选**旧备份**扫描源，不是日常容器，也不是永久库 |
| 整份 `%USERPROFILE%\.cursor` 或整个项目根 | 不应登记成「一条资产」；管的是其下的 skill/rule 等条目 |

### 5.4 Cursor Rule 生效层级（本机实测 2026-07-26）

CCM 仍可扫描 / 部署 `%USERPROFILE%\.cursor\rules` 与 `{项目}\.cursor\rules` 下的文件；但 **Cursor Agent 是否读取这些文件当 Rule**，与「文件是否在容器目录」不是一回事。下列为冲突探测（互斥语言指令 + 首行 `TOKEN=`）的**已验证**结论。

#### 5.4.1 Cursor 实际认的来源（与 CCM「容器」对照）

| 来源 | 是什么 | 起什么作用 | CCM 能否当「容器路径」管 |
|------|--------|------------|--------------------------|
| **User Rules（设置）** | Cursor **Settings / Customize → Rules** 里的纯文本 | 全局偏好，跨项目进 Agent | **否**（不在磁盘容器树里；须用户在设置中维护） |
| **Project Rules（项目）** | 当前工作区 `{项目根}\.cursor\rules\*.mdc`（可含 `alwaysApply` / globs） | 仅该工作区；冲突时盖过 User Rules | **是**（项目级 `.cursor` 活动容器） |
| **用户目录 `~\.cursor\rules\*.mdc`** | 本机用户级容器下的 rule 文件 | CCM 可扫描部署；**当前 Cursor 不会把它当作全局 User Rules / 全局 Always Apply 的 `.mdc` 源** | 文件可管，但**不等于 Agent 已加载** |
| **永久库 `rules/`** | 停用仓库副本 | 不进 Agent | 库内不管「生效」 |

官方文档冲突顺序（文档）：**Team Rules → Project Rules → User Rules（Settings）**。  
社区说明（论坛）：**尚不支持**从 `~/.cursor/rules` 全局加载 `.mdc`；跨项目规则请用 Settings 的 User Rules。

#### 5.4.2 实测步骤摘要

1. Settings 临时粘贴西班牙文 + `TOKEN=L1-SETTINGS`。  
2. `~\.cursor\rules\zz-lang-hierarchy-test-userdir.mdc`：韩文 + `TOKEN=L2-USERDIR`，`alwaysApply: true`。  
3. `{工作区}\.cursor\rules\zz-lang-hierarchy-test-project.mdc`：英文（后改为中文探测文案）+ 项目侧 TOKEN，`alwaysApply: true`。  
4. 新开 Agent，要求首行输出 `TOKEN=`。

#### 5.4.3 实测结果

| 条件 | 助手首行 TOKEN / 语言 | 结论标注 |
|------|----------------------|----------|
| L1 Settings + L3 项目 rule 同时启用；L2 未出现在 Applied 列表 | `TOKEN=L3-PROJECT`，英文 | **已验证**：Project > Settings |
| 删除 / 关闭项目 L3；L1 仍在 Settings | `TOKEN=L1-SETTINGS`，西班牙文 | **已验证**：无项目冲突时 Settings 生效 |
| 删除 Settings 粘贴段；项目侧仍有探测 rule | `TOKEN=PROJECT_WINS`，中文（项目文案） | **已验证**：仅项目 rule 时项目生效 |
| `~\.cursor\rules\zz-lang-hierarchy-test-userdir.mdc` 始终在磁盘且 `alwaysApply: true` | 从未出现 `TOKEN=L2-USERDIR`；Applied 列表也不见该条 | **已验证**：用户目录 `.mdc` **未**作为全局 Rule 注入 |

#### 5.4.4 对 CCM 产品逻辑的含义

1. **「放入用户级 `.cursor\rules`」≠「Cursor Rule 已全局生效」**——对 **rule** 尤其如此；skills 等其它 kind 仍按工具约定读用户级目录，勿与 Rule 层级混谈。  
2. **要让某条 rule 在当前项目 Agent 里 Always Apply**：部署到 **该项目** `{项目}\.cursor\rules`，并在 Cursor Rules 面板确认为 Always Apply。  
3. **要让偏好跨所有项目生效**：写入 **Settings → Rules**（纯文本），不要指望只往 `~\.cursor\rules` 丢 `.mdc`。  
4. 永久库副本仍然**从不**直接生效（与 §1 / §4 一致）。  
5. 界面若提示「打开库 / 打开永久库」，打开的是磁盘路径，**不**表示 Cursor 已加载该 rule。  
6. **UI**：在导航「通用 · Cursor」且「容器中」含规则条目时，节标题下显示黄条：提示将正文复制到 Cursor → Settings → Rules（勿误以为用户级放入即全局生效）。  
7. **缺失**：库文件与容器路径皆不存在时进「缺失」区。界面提示可「打开曾用路径」到上级目录、查回收站恢复后刷新；有意删除则「清理缺失」只删台账、不再显示。

## 6. 思路优化：建议怎么记这套逻辑

把你原来的四点收成一条链，比并列四问更好记：

```text
谁痛（散落 + 同名多版本分不清定稿 + 难复用对账）
  → 给谁（多工具多项目、配置会反复改的个人开发者）
    → 办法（永久库=权威定稿；容器=生效副本；哈希比对；冲突时人选）
      → 边界（默认只碰 .cursor / .claude / .codex+.agents 约定路径）
```

四条硬边界口诀：

1. **库 ≠ 生效**：永久库是仓库与权威定稿；容器才是工具入口。  
2. **同名 ≠ 同版**：文件名相同只说明标签像，是否同一版看内容哈希；异内容必须人选。  
3. **台账 ≠ 正文 / 永久库 ≠ BackupRoot**：`catalog.json` 管位置与身份，不解释 skill 语义（[00](00-工作面隔离原则.md)）；界面「永久库」不是设置项 `BackupRoot`（旧备份扫描源）。  
4. **Cursor Rule：项目 `.mdc` / Settings 文本才进 Agent**；`~\.cursor\rules\*.mdc` 可被 CCM 管理，但**当前不等于**全局 User Rules（见 §5.4）。
