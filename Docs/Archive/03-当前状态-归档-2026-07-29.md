- **刷新冲突比对**：工具栏「刷新」先只读收集「容器存活副本 ↔ 永久库正本」哈希不同项；有冲突则弹决议窗，确认后才对账+应用；无冲突则刷新本身视为确认并对账
- **冲突并排 Diff**：比对区固定两列等高、滚动同步；行级增删着色；skill 目录解包 `SKILL.md` 再算大小/哈希/预览（避免 0 B 与只列文件夹名）
- **修复刷新决议键**：`refresh:` / `move:` 逻辑键不得经 `path.resolve` 规范化（否则决议被静默跳过、磁盘未同步、再刷新仍弹窗）；`normalizeConflictResolutionKey` 对逻辑键仅 trim+小写；merge/overwrite 成功后做双边哈希校验，失败计入 `failed`
- **`-哈希` 后缀语义**：仅「另存为新 id」（saveAs）或历史静默另存会用内容哈希前 8 位生成新 id（如 `L2P-…-947d0166`）；merge/overwrite **不会**改 id
- **修复保留库版副作用**：`syncLibraryContentToContainer` / 写库改为临时路径再替换（失败不先删空容器）；刷新 merge/overwrite 作用无后缀正本、写回 `deployedPath`，并清理同容器路径上的 `id-xxxxxxxx` 误另存孪生；`failed>0` 时 UI 展示 errors 且不关冲突窗；遗留 `ingest()` 的 merge 改为库盖容器、无决议禁止默认 saveAs
