## 定稿细节

### Electron 二进制与 Node 20

- 现象：`electron` 的 install 在 Node 20 上因 `@electron/get` ESM 失败。
- 机制：从 `%LOCALAPPDATA%\electron\Cache` 解压 zip 到 `node_modules/electron/dist/`，写 `path.txt` 为相对路径 `electron.exe`。
- 入口：`scripts/ensure-electron.mjs`；`predev` / `prestart` 调用。

### Preload 与主进程

- Vite 打包 preload 曾导致 `require is not defined`；改为仓库内 `electron/preload.cjs`。
- `main` 通过 `createRequire` 取 `BrowserWindow` 等（纯 ESM named import 易失败）。
- 无边框：`frame: false`；拖区在工具栏 CSS `-webkit-app-region: drag`。

### 设置与台账

- Settings 键含：`LibraryRoot`、`LibraryRootConfigured`、`UiNavWidth`、`UiListWidth`、`UiNavVisible`、`UiDetailVisible`、`NavKind`、`LastActionLog` 等。
- Catalog 条目字段以 camelCase 为准；读入时兼容旧 PascalCase 项目项。
- 双份态：`isInLibrary=true` 且 `deployedPath` 非空 = 库正本 + 容器副本并存；永久库列表用 `isInActiveUse` 标绿边，不再从库区排除。

### 部署 Copy 与存回比对

- `deployToContainer`：复制（`fsMove` 的 copy*），库文件保留；禁止再依赖「库为空」判断使用中。
- 移出/迁入：内容哈希相同 → 静默删容器侧；不同 → 冲突窗（大小/mtime/预览）决议；`merge` = 保留库版并删容器副本。
- 关键服务：`skillIngestService.ts`、`libraryCatalogService.ts`。

### 状态点（checkpoints，已退役）

- 曾用于「恢复初始」目标下拉；2026-07-27 起不再写入、无 UI。
- 旧 `catalog.json` 中的 `checkpoints` 可读忽略；日常用放入 / 刷新。

### UI 命令面与主区布局

- 顶栏：扫描建库 | 设置永久库 | 刷新 | **左/右侧栏 layout toggle** | 窗控。
- 项目树 / 库列表 / 空白区：ContextMenu 覆盖原工具栏按钮能力；条目右键先 `setSelection` 再按新 `commands` 弹菜单。
- `WorkbenchSplit` + `SplitViewModel`（`src/layout/`）：导航/详情 `LayoutPriority.Low`（缩窗先吸）、列表 `High`；min 左/右 180、列表 280。
- 隐藏侧栏时从 panes 移除；再显示恢复上次宽度。栏宽仅在 settings snapshot 首次灌入（`restoreKey`），避免与 sash 拖拽回写打架。

### 详情 Markdown Crepe 与多页签 `nodes`（2026-07-27）

- **现象**：红条 `Context "nodes" not found`；常「第一页签正常、第二页签起失败」；`npm start` 生产试跑多次连开正常，`npm run dev` 易复现。
- **机制**：
  1. Milkdown ctx 切片按模块单例身份识别；Vite 开发预构建若拆出多份 `@milkdown/ctx|core|utils`，自定义插件与 Crepe 内置 schema 各看一份 → `nodes`「找不到」。
  2. 模块级 `$prose` 单例被多个 `DetailMarkdownCrepe` `editor.use` → 第二实例炸。
- **对策**：
  - `createEnterContractProse()` 工厂（`src/lib/enterContract.ts`），每次 create 新 `$prose` + 新 `PluginKey`。
  - `vite.config.ts`：`resolve.dedupe` + `optimizeDeps.include`（`MILKDOWN_DEDUPE`）；仅 `command==='serve'` 给 electron 主进程 `build.watch`。
  - 源码统一 `@milkdown/kit/core|utils|prose/*`（勿再直连 `@milkdown/utils` 等）。
  - 失败条展示 `err.message`；create 单飞；error/timeout 禁止 ResizeObserver 连环重试。
- **排障口令**：停 dev → 删 `node_modules/.vite` → 重开 → 连开 ≥3 页签。
- **详录**：[Research/012-详情Markdown多页签Context-nodes-not-found-2026-07-27](Research/012-详情Markdown多页签Context-nodes-not-found-2026-07-27.md)。

### 详情 Markdown 最小差异写回（2026-07-28）

- **现象**：改一字再删 / 改一行保存 → VSCode 大片 diff（hr/列表/表格/EOL）；续现：只改标题仍把 `*` 列表洗成 `-`。
- **机制**：磁盘原文 O 与序列化基线 S0 本就不等；旧 dirty 用 O 比 S1；保存写出整篇 S1。写死 `bullet:'-'` 时 O↔S0 列表行对不上 → 回验失败 → 整篇兜底。
- **对策**：
  - dirty：`S1 !== S0`（`baselineMdRef = crepe.getMarkdown()`）。
  - 写盘：`mergeSerializedEdit(O, S0, S1)`；O↔S0 用 `normalizeLineForAnchor`；merge 非 null 即写 merged（回验仅 warn）。
  - `inferRemarkStringifyOptions(O)` → `remarkStringifyOptionsCtx`（按原文多数票设 bullet/rule）。
  - 仅 `merge === null` 才 `withDominantEol(S1)`。
  - `saveDetailMarkdown` 内容相同跳过写盘与 `contentHash`。
- **详录**：[Research/013-详情Markdown保存最小差异写回-2026-07-28](Research/013-详情Markdown保存最小差异写回-2026-07-28.md)。

## 踩坑与边界

| 坑 | 边界 / 对策 |
|----|-------------|
| path.txt 写成绝对路径 | 必须相对名 `electron.exe` |
| 已配置 LibraryRoot | 不会再强制改成 `C:\CursorSkills` |
| Move 入库 | 仅确认预览后执行；取消不改磁盘 |
| 旧 Move 部署遗留 | 可能仅容器有文件（`isInLibrary=false`）；新部署走 Copy |
| `Archive/legacy-wpf` | 不参与 npm 构建；已归档，仅对照 |
| 代码去「读懂」skill/rule 正文 | **禁止**；只认路径与已约定元数据。见 [00-工作面隔离原则](00-工作面隔离原则.md) |
| 手改 catalog 时软件仍在跑 | 管理器会整体回写 catalog，易覆盖手改；改库文件时先退出软件 |
| `deployedPath` 单值 | 同一条目多容器同时部署不支持 |
| Crepe 多页签 `Context "nodes" not found`（仅 dev） | 禁止共享 `$prose` 单例；Vite 必须 `dedupe` Milkdown；导入走 kit；见 Research/012 |
| Crepe 保存整篇规范化 | dirty 比序列化基线；化妆品锚点；仅 merge=null 整篇兜底；见 Research/013 |
| 回验失败就整篇 S1 | **禁止**；merge 成功则写 merged，保原文 `*`/`***` |
| 编辑表格内部 | 该表可能被序列化重排（远端表不动）；属 GFM table stringify 限制 |
| `npm run build` 挂住不退出 | 曾因 electron 插件始终 `build.watch`；现仅 serve 启用 |
| 静默吞掉 `crepe.create` 异常 | 必须 UI/`console.error` 打出 `err.message`，否则难定位 |
| 仅有 Electron CSP 开发警告 | 与 `nodes` 故障无关，勿当根因 |
