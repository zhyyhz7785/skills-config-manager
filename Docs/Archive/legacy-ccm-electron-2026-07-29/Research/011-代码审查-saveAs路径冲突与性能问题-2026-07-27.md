### 3. 【高】retireHashSuffixOrphans基于id模式删除文件，存在误删风险

**位置**: `code/CursorConfigManager/electron/services/skillIngestService.ts:2363`

**机制**: `retireHashSuffixOrphans` 通过正则 `/^${baseId}-[0-9a-f]{8}$/i` 识别"saveAs孪生项"并删除，但任何id恰好以8位十六进制结尾且共享容器路径的合法条目都会被误判为孤儿。

**触发条件**: 
- 用户创建id为 `myskill-abc12345` 的条目（恰好8个hex字符）
- 容器路径与另一个id为 `myskill` 的条目相同
- 执行refresh冲突解析时，`retireHashSuffixOrphans` 误判为saveAs孤儿 → 删除库文件（递归删除目录或unlink文件）+ 移除catalog行 → **不可逆的数据丢失**

**代码**:
```typescript
// Line 2369-2372: 纯模式匹配构造正则
const re = new RegExp(
  `^${baseId.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')}-[0-9a-f]{8}$`,
  'i',
);

// Line 2378-2394: 删除匹配项
if (!re.test(e.id)) continue;
if (!entryPointsToContainerPath(e, containerPath)) continue;
// ... 删除库文件
fs.rmSync(full, { recursive: true, force: true });
// ... 删除catalog行
catalog.remove(e.id);
```

**根源**: 历史saveAs从未记录来源关系，现在依赖命名启发式反向工程关系。

**深层修复**: saveAs分配id时记录显式字段（如 `savedAsOf: canonicalId`），retire/canonicalize按该字段判断而非模式匹配。

**验证**: Altitude角度发现 → 已验证**CONFIRMED**
