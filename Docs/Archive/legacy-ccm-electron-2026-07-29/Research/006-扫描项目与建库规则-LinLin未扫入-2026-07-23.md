# 扫描项目 / 扫描建库规则（含 LinLin 案例与 2026-07-23 修正）

> 依据：`projectDiscoveryService.ts`、`scanScopeHelper.ts`、`skillScanService.ts`、`skillIngestService.ts`、`appController.ts`。  
> 关联：[004-目录录入映射](004-目录录入映射-Cursor-Claude-Codex-2026-07-21.md)。

---

## 1. 结论（现行规则）

「扫描建库」已是**完整闭环**：在合法扫描范围内发现所有含 `.cursor` 的**项目根** → 确认时写入 `catalog.projects` → 再登记容器内合法资产到 `catalog.entries`。  
**不再依赖**用户先点「扫描项目」；未登记项目（如 `E:\LinLin`）只要落在扫描根 + 深度内，就会被建库发现并登记。

| 项 | 现行行为 |
|----|----------|
| 默认扫描根 | `ProjectScanRoots` 为空 → **所有可读盘符**（`ProjectDiscoveryService.getDefaultScanRoots`） |
| 配置扫描根 | `settings.ProjectScanRoots` 有有效路径时**只用配置** |
| 项目根 | 含 `.cursor` 的父目录（登记 `E:\LinLin`，不是 `E:\LinLin\.cursor`） |
| 空 `.cursor` | **仍登记项目**（可作放入目标） |
| 用户级容器 | 仍走专用通道（`%USERPROFILE%\.cursor` 等），不当普通项目 |

### 历史根因（已修复前）

曾默认只扫备份库父目录（如 `E:\cursor`），且建库只扫已登记项目 → `E:\LinLin` 两环皆断。2026-07-23 起改为默认全盘符 + 建库内合并发现。

## 2. 关键前提：路径语义

| 概念 | 正确路径 | 错误用法 |
|------|----------|----------|
| **项目根**（登记用） | `E:\LinLin` | 把 `E:\LinLin\.cursor` 当成项目根 |
| **容器**（Cursor 生效） | `E:\LinLin\.cursor` | 期望把 `.cursor` 本身登记为项目 |

误登记 `.cursor` 为项目根时，资产扫描会找 `...\ .cursor\.cursor`，结果为空。`addProject` 仅禁止用户主目录 / `%USERPROFILE%\.cursor`。

## 3. 「扫描建库」现行流程

```text
resolveProjectScanRoots
  → ProjectDiscoveryService.scan（+ origins 溯源补全）
  → mergeProjectsForContainerScan（已登记 ∪ 未登记稳定 id；更深根优先）
  → SkillScanService.scanAll（用户级 + 合并后的项目容器）
  → 用户确认 confirmScanBuild
       → addProject（本轮 pending）
       → registerFromScan（资产，不 Move）
       → rematchProjectScopes
```

UI 顶栏「扫描建库」只调用 `scanAndIngestPreview` → `confirmScanBuild`（不再先跑独立「扫描项目」以免全盘双倍遍历）。  
IPC `scanProjectsPreview` / `confirmScanProjects` 仍保留，供其它入口兼容。

### 资产识别（摘要）

- skill：`skills/{name}/SKILL.md`
- rule：`rules/**` 下 `.mdc`/`.md`（跳过 `backup`、`knowledge`、`.full.md`）
- 污染跳过：`skills-cursor`、`.cursor/**/backup`、损坏重解析点等

### 建库 vs 迁入

| 动作 | 磁盘 | 台账 |
|------|------|------|
| 扫描建库 / `registerFromScan` | 文件留在容器 | 记 origins / deployedPath |
| 迁入备份库 | 文件进 `SkillsLibraryRoot` | `isInLibrary=true` |

## 4. 「扫描项目」规则（发现层，建库复用）

| 规则 | 说明 |
|------|------|
| 自动候选 | markers 含 `cursor`（仅 `.claude`/`.agents` 不自动） |
| 深度 | `ProjectScanMaxDepth`（默认 5，上限 12） |
| 排除 | 用户 `.cursor` 子树、备份库子树、`node_modules`/系统目录、编辑器 extensions 等 |
| 嵌套 | 父级有 `.cursor` 仍继续向下；不进入 `.cursor` 内部再当「项目」扫 |

未登记根在预览阶段使用 `stableProjectIdForRoot(path)`（路径 SHA256 前 32 位），确认写入后 `rematchProjectScopes` 按最长项目根校准 scope。

## 5. 边界与取舍

| 选择 | 收益 | 代价 |
|------|------|------|
| 默认全盘符 | LinLin 类盘符同级项目不再漏扫 | 首次建库可能较慢；依赖排除名单 |
| 建库内自动登记项目 | 一步闭环；空容器可放入 | 导航项目变多；误扫依赖排除质量 |
| 更深项目优先扫描 | 嵌套 `.cursor` 资产 scope 归子项目 | 依赖路径深度排序 + 事后 rematch |

**配置收窄**：若只需扫某几棵树，在 `%APPDATA%\CursorConfigManager\settings.json` 设置 `ProjectScanRoots`（例如 `["E:\\LinLin"]` 的父路径或 `E:\\`）。
