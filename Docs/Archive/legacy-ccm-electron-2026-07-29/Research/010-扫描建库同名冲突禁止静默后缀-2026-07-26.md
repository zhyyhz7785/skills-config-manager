# 扫描建库：同名比对与冲突决议（禁止静默 `-哈希`）

日期：2026-07-26

## 问题

删除 `catalog.json` 后刷新 + 扫描建库，会出现 `first-principles-*-9e6fcf1a` 一类条目：同名资产被静默另存为 `id-前8位内容哈希`。

## 根因

1. `registerFromScan` 在同名且内容不同、无用户决议时，默认 `allocateUniqueId(\`${id}-${hash.slice(0,8)}\`)`。
2. 刷新时 `relinkActiveContainerDualCopies` 对活动容器调用 `registerFromScan(..., [])`，空决议也会触发上述静默另存。

## 现行策略

| 情况 | 动作 |
|------|------|
| 内容哈希与库内已有相同 | 合并来源 / 回链 `deployedPath`，不新建 id |
| 永久库磁盘无此资产 | 确认建库时**复制**进永久库并登记（保留容器副本） |
| 永久库有同名但哈希不同 | 弹出冲突窗；用户选保留库版 / 覆盖库 / 另存新 id / 跳过 |
| 禁止 | 无确认时静默 `id-xxxxxxxx` |

刷新软登记：`skipConflictsSilently`——有同名冲突则跳过，留给扫描建库弹窗。

扫描建库预览返回 `conflicts`；UI 先决议再 `confirmScanBuild(selectedKeys, resolutions)`。

## 同一文件判定 + 规则扁平落盘（2026-07-26 补）

假冲突根因：库内曾落盘为 `rules/{id}/{文件}`，比对却对**目录壳**算哈希，与容器扁平 `.mdc` 永远不同。

| 约定 | 说明 |
|------|------|
| 判定 | 只比正文字节哈希；`rules/{id}/` 解包到主 `.mdc`/`.md` 再比 |
| 新写入 | 单文件 rule → 扁平 `rules/{basename}`（如 `rules/01.mdc`） |
| 复制 | 字节拷贝，不注入 frontmatter / 文件头 |
| 存量 | 不强行搬家；同内容只回链；覆盖时改扁平并清旧目录壳 |
| merge（扫描建库） | 「保留永久库版本」= **用库覆盖容器**；「用容器覆盖永久库」才改库正文 |

**说明**：`01.mdc` 若两边正文字节不同，弹冲突是预期。
