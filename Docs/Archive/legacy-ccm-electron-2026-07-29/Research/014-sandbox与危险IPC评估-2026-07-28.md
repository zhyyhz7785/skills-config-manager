# 014 · sandbox 与危险 IPC 评估

> **日期**：2026-07-28  
> **结论（已验证）**：`BrowserWindow` 已开 `sandbox: true`（仍 `contextIsolation` + 无 `nodeIntegration`）；静态 `electron/preload.cjs` 仅暴露 `ccm.invoke`，与 sandbox 兼容。生产 `npm run build` + `npm start` 可起窗。高危写盘 IPC 多数已有 UI 确认或冲突窗；补齐「空 .cursor 删项目」静默路径的 `confirm`。

---

## 1. 渲染进程隔离

| 项 | 状态 |
|----|------|
| `contextIsolation` | `true` |
| `nodeIntegration` | `false` |
| `sandbox` | **`true`**（本轮开启） |
| preload | `electron/preload.cjs` → `contextBridge.exposeInMainWorld('ccm', { invoke })` |
| IPC 通道 | 单一 `ccm:invoke` + `IpcMethod` 白名单（`shared/ipc.ts`） |

渲染进程无法直接 `fs` / `child_process`；破坏性操作必须经主进程。

---

## 2. IPC 风险分级

| 级别 | 方法（节选） | 处置 |
|------|----------------|------|
| **高** | `purgeMissing` | UI：`window.confirm`（已有） |
| **高** | `removeProject`（有文件 → `forceDeleteMarkers`） | UI：删除项目模态（已有） |
| **高** | `removeProject`（无文件 / 无 .cursor） | UI：本轮补 `window.confirm`（此前静默） |
| **高** | `confirmIngest` / `moveIntoBackupLibrary` / `withdraw` / `applyRefreshConflicts` / `confirmScanBuild` | 预览窗或冲突决议窗即确认；主进程路径护栏（Plan/04） |
| **中** | `deploy`、`withdraw`（无冲突直删副本）、`saveDetailMarkdown`、`editTags`、`setScope*` | 用户显式菜单/快捷键；写路径受管校验 |
| **低** | `getSnapshot`、布局/筛选、`open*Directory` / `openPath` | 只读或仅打开资源管理器；不另加确认 |

未做：按方法拆 channel、capability token、CSP 全站。
