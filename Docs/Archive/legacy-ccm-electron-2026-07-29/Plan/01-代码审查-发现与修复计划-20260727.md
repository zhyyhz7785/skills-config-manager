## 2. 严重 / 高：机制与验收

### C1 · 台账损坏可被写回为空（严重）

**机制（已验证）**

1. `writeCatalogFile` 直接 `writeFileSync(catalogPath, …)`，无 temp+rename。
2. `load()` 任意异常（含半截 JSON）→ `this.catalog = createEmptyLibraryCatalog()`。
3. `snapshotCatalogHistory` 在 `entries.length === 0` 时**不备份**。
4. `buildSnapshot` 几乎每个 IPC 成功路径都会 `catalog.load()`，放大「读到残缺 → 内存变空 → 后续 `save` 写盘」窗口。

**建议修复**

- 写入：`catalog.json.tmp` → `fsync` → `rename` 覆盖。
- 读取失败：保留上次成功内存态；或拒绝后续写盘并表面错误；禁止静默空台账覆盖磁盘。
- 写空前强制再读盘比对 / 要求显式「确认清空」。
- 历史快照：在写盘**前**对非空磁盘文件做备份（即使内存已空也要能救）。

**验收**：人为截断 `catalog.json` 后任意 UI 操作，磁盘文件不得被空数组覆盖；应有可读错误与可恢复历史。

---

### C2 · rule 的 saveAs 路径碰撞（严重）

**机制（已验证）**：`preferredId` 已改为 `id-xxxxxxxx`，但 flat 规则仍：

```669:669:electron/services/skillIngestService.ts
                  ? path.join(folder, path.basename(item.sourcePath))
```

两项目同名 `auth.mdc` 另存后均写 `rules/auth.mdc`，后者覆盖前者，台账 id 与文件脱节。

**对照**：刷新路径 saveAs（~1033–1040）对规则已有「候选存在则改名」分支；扫描建库路径未对齐。

**建议修复**：rule 单文件落盘与 id 绑定（如 `rules/{id}{ext}` 或 `rules/{stem}-{shortId}{ext}`）；与刷新 saveAs 共用同一路径策略。

**验收**：两源同 basename、不同哈希、均选 saveAs → 库内两个文件、两条台账、互不覆盖。

---

### C3 · 哈希后缀孤儿清理误删（严重）

**机制（已验证）**：`retireHashSuffixOrphans` 用 `/^baseId-[0-9a-f]{8}$/i` + 同容器路径匹配后 `rmSync`/`catalog.remove`。合法 id（如用户自建 `myskill-abc12345`）可被误判。

**建议修复**：saveAs 时写显式字段（如 `savedAsOf`）；retire 只删该字段指向正本的孪生。过渡期：模式匹配仅作提示，默认不删盘。

**验收**：正本 + 合法「像后缀」id 共存时，merge/overwrite 不得删后者库文件。

---

### C4 · 迁入删副本失败仍标成功（高）

**机制（已验证）**：同哈希迁入分支 `catch { // ignore }` 后仍 `deployedPath=''`、`moved++`。

**建议修复**：删失败 → `failed++`、保留 `deployedPath`、表面错误；禁止在未确认删除成功时改台账。

**验收**：对容器文件加只读/锁后迁入，台账仍显示在容器侧，不得假「已迁入」。

---

### C5 · 每快照软登记 + 全量哈希（高）

**机制（已验证）**：`relinkActiveContainerDualCopies` 在快照路径调用 `registerFromScan(..., skipConflictsSilently: true)`，内部对发现项 `hashPath`（同步读盘）。

**建议修复**：软登记节流（仅容器变更/手动刷新）；哈希 memo（mtime+size 短路）；`isConfigured` 门闩（与 C7 一并）。

**验收**：库内数十项时，纯筛选/选中操作主进程无明显同步卡顿（本机体感或采样）。

---

### C6 · `libraryPath` 无 containment（高）

**机制（已验证）**：`path.join(libraryRoot, entry.libraryPath)` 后读写删（详情保存、合并删库、`tryDeleteLibraryContent`）均未强制 `pathRules.isUnderDirectory(full, libraryRoot)`。源路径侧多处已有 `isUnderDirectory` 检查，**库相对路径侧缺失**。

**建议修复**：所有「库根 + libraryPath」解析统一经 `resolveLibrarySafePath`；越界则拒绝操作并记错。

**验收**：台账中植入 `..\..\...\...` 相对路径时，保存/删除/部署均失败且不触碰库外文件。
