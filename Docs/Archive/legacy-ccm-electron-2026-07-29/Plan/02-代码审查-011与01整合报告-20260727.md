## 4. 统一机制摘要（严重 / 高）

### U1 · 台账可被写空（严重）— 01 独有，优先于多数 diff 缺陷

- `writeCatalogFile`：直接 `writeFileSync`，无 temp+rename。
- `load()` catch → 空台账；`snapshotCatalogHistory` 在 `entries.length===0` 时不备份。
- 几乎每个 IPC 的 `buildSnapshot` → `catalog.load()`，放大残缺 JSON 窗口。

**修复要点**：原子写；load 失败保留上次成功内存 / 禁止写空覆盖盘；写前备份磁盘非空文件。

### U2 · rule saveAs 路径碰撞（严重）— 共有

- id 已 `allocateUniqueId(...-hash)`，落盘仍 `path.join(folder, path.basename(sourcePath))`（~669）。
- 刷新路径 saveAs（~1033–1040）已有改名分支，扫描建库未对齐。

**修复要点**：rule 路径与 id 绑定；与刷新 saveAs 共用策略。

### U3 · retire 模式误删（严重）— 共有

- `/^baseId-[0-9a-f]{8}$/i` + 同容器路径 → `rmSync` + `catalog.remove`。
- 合法 `myskill-abc12345` 可被误杀。

**修复要点**：`savedAsOf`（或等价血缘字段）；过渡期默认不删盘。

### U4 · 迁入假成功（高）— 01 独有

- 删容器副本 `catch { ignore }` 后仍 `deployedPath=''`、`moved++`。

**修复要点**：删失败不改台账。

### U5 · 每快照哈希（高）— 共有

- `relinkActiveContainerDualCopies` → `registerFromScan(skipConflictsSilently)` → 同步 `hashPath`。

**修复要点**：节流 + memo；与 U7 共用 `isConfigured` 门闩。

### U6 · libraryPath 穿越（高）— 01 独有

- `path.join(libraryRoot, libraryPath)` 后读写删无 `isUnderDirectory`；源路径侧已有检查，库相对路径侧缺失。

**修复要点**：统一 `resolveLibrarySafePath`。
