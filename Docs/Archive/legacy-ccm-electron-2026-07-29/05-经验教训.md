## 经验条目

### Electron 二进制与 Node 20

- **日期**：2026-07-21
- **症状 / 背景**：`electron` install 在 Node 20 上因 `@electron/get` ESM 失败；`path.txt` 写绝对路径会假触发 “Downloading Electron…”。
- **走过的弯路**：
  1. 依赖 npm 安装脚本自动拉二进制 → Node 20 直接失败。
  2. `path.txt` 写绝对路径 → 误触发下载并再踩 ESM。
- **最终正确做法（已验证）**：从 `%LOCALAPPDATA%\electron\Cache` 解压 zip 到 `node_modules/electron/dist/`；`path.txt` 只写相对名 `electron.exe`；入口 `scripts/ensure-electron.mjs`（`predev` / `prestart`）。
- **关键文件**：
  - `scripts/ensure-electron.mjs` — 解压与 path.txt 修复
- **禁止再犯**：`path.txt` 写绝对路径；在 Node 20 上假定 `npm install` 能装全 electron。

### Preload 与主进程

- **日期**：2026-07-21
- **症状 / 背景**：Vite 打包 preload 出现 `require is not defined`；纯 ESM named import `BrowserWindow` 易失败。
- **走过的弯路**：
  1. 让 Vite 打包 preload → CJS/ESM 混用炸。
  2. 主进程纯 ESM named import electron API → 运行失败。
- **最终正确做法（已验证）**：仓库内静态 `electron/preload.cjs` + `require('electron')`；`main` 经 `createRequire` 取 API；无边框 `frame: false`，拖区 CSS `-webkit-app-region: drag`。
- **关键文件**：
  - `electron/preload.cjs` — 暴露 `window.ccm`
  - `electron/main.ts` — 窗口与 IPC
- **禁止再犯**：把 preload 交回 Vite 打包管线。

### 部署 Copy 与存回比对

- **日期**：2026-07-25
- **症状 / 背景**：旧 Move 部署导致「使用中库为空」；同名文件多副本难定稿。
- **走过的弯路**：
  1. Deploy=Move，库侧文件被挪走 → 列表与「权威定稿」语义崩。
  2. 用「库是否为空」判断使用中 → 双份态无法表达。
- **最终正确做法（已验证）**：`deployToContainer` 复制，库正本保留；台账双份态 `isInLibrary` + `deployedPath`；移出/迁入哈希同删异选；`merge`=保留库版并删容器副本。
- **关键文件**：
  - `electron/services/skillIngestService.ts` — Deploy/Withdraw/冲突
  - `electron/services/libraryCatalogService.ts` — 台账
- **禁止再犯**：再依赖「库为空」判断使用中；Deploy 默认 Move。

### 详情 Markdown 多页签 `nodes`

- **日期**：2026-07-27
- **症状 / 背景**：红条 `Context "nodes" not found`；常「第一页签正常、第二页签起失败」；`npm start` 少见、`npm run dev` 易复现。
- **走过的弯路**：
  1. 模块级 `$prose` 单例被多编辑器 `editor.use` → 第二实例炸。
  2. Vite 开发预构建拆出多份 `@milkdown/*` → ctx 切片身份不一致。
  3. 静默吞 `crepe.create` 异常 / 误把 CSP 警告当根因 → 难定位。
- **最终正确做法（已验证）**：`createEnterContractProse()` 每编辑器新实例；`vite.config.ts` `resolve.dedupe` + `optimizeDeps.include`；源码统一 `@milkdown/kit/*`；失败条展示 `err.message`；仅 serve 启用 electron `build.watch`。排障：停 dev → 删 `node_modules/.vite` → 重开。
- **关键文件**：
  - `src/lib/enterContract.ts` — 工厂，禁止模块单例
  - `src/components/DetailMarkdownCrepe.tsx` — Crepe 宿主
  - `vite.config.ts` — Milkdown dedupe
- **禁止再犯**：共享 `$prose` 单例；直连 `@milkdown/utils|core|prose`；忽略 `err.message`。
- **相关**：[Research/012](Research/012-详情Markdown多页签Context-nodes-not-found-2026-07-27.md)

### 详情 Markdown 最小差异写回

- **日期**：2026-07-28
- **症状 / 背景**：改一字再删仍整篇规范化；续现只改标题仍把 `*` 列表洗成 `-`。
- **走过的弯路**：
  1. dirty 用磁盘原文 O 比序列化全文 S1 → 假脏 + Ctrl+S 整篇洗稿。
  2. 写死 `bullet:'-'` → O↔S0 列表行对不齐 → 回验失败 → 整篇兜底。
- **最终正确做法（已验证）**：dirty 用 `baselineMdRef=getMarkdown()`（S0）；`mergeSerializedEdit(O,S0,S1)` 反投影；`inferRemarkStringifyOptions(O)` 按原文多数票设 bullet/rule；merge 非 null 即写 merged（回验仅 warn）；仅 merge=null 才整篇兜底。
- **关键文件**：
  - `src/lib/markdownMinimalMerge.ts` — 反投影合并
  - `src/components/DetailMarkdownCrepe.tsx` — save 路径
- **禁止再犯**：回验失败就整篇写 S1；写死 bullet 忽略原文标记。
- **相关**：[Research/013](Research/013-详情Markdown保存最小差异写回-2026-07-28.md)
