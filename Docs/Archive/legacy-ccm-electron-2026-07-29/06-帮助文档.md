# 帮助文档

> 面向最终用户（小白优先）。开发者编译与验收见 [04-启动与测试](04-启动与测试.md)。

## 软件是做什么的

把 Cursor / Claude / Codex 用的 **skills、rules** 等配置，集中放在本机「永久库」里记账；需要生效时 **放入** 到对应项目的 `.cursor`（等）容器，不需要时 **移出** 回库。避免多项目文件散落、难以对账，以及同名文件多份改稿后分不清哪份是定稿。

更完整的产品说明见 [01-核心逻辑](01-核心逻辑.md)。

## 推荐流程（最短路径）

1. 打开本软件（开发者用 `npm run dev`；或运行便携包，路径见 [04-启动与测试](04-启动与测试.md)「发行路径」）。
2. 首次未设置库时，会使用默认永久库 `C:\CursorSkills`（自动建目录）。
3. 需要发现本机项目/资产时，点顶栏 **扫描建库**（启动**不会**自动弹扫描预览）：看清将登记的内容 → **确认**，或 **取消**跳过。
4. 左侧选 **项目** 或 **用户级** 导航；中间列表对条目 **直接右键** 即可（会自动选中该行）。
5. 需要生效：**右键 → 放入**；不需要时 **右键 → 移入永久库**。
6. 改库路径：顶栏 **设置永久库**。

## 界面说明

| 区域 | 作用 |
|------|------|
| 顶栏 | **扫描建库**、设置永久库、刷新；**左/右侧栏开关**；最右最小化/最大化/关闭 |
| 左栏 | 项目树 / 导航（可拖宽；最小约 180px；缩窗时优先被压缩；可整栏隐藏） |
| 中栏 | 库条目列表（可拖宽；最小约 280px；缩窗时尽量保持宽度） |
| 右栏 | 详情与说明（可贴齐右缘；最小约 180px；缩窗时优先被压缩；可整栏隐藏）。**摘要**台账字段；**Markdown** 所见即所得（顶部显示当前文件名，改后圆点，无保存按钮，`Ctrl+S` 保存；`Ctrl`+滚轮缩放、`Ctrl+0` 复位；页签右端「样式」打开主题画廊调排版/布局/细节）；**原文**只读源码 |
| 右键菜单 | 主要操作都在这里；点在条目上会先选中再出菜单 |

## 常见问题

**Q：换库或刚打开后，右键「放入」是灰的？**  
A：应已自动选中右键那一行后再出菜单。若仍灰：该条目当前不可放入（例如已在容器里有副本，或库文件缺失）。可先左键点一下再右键对照。

**Q：「设为层级」会改文件名吗？**  
A：不会。只在台账写入 `tags.level`，影响「按层级用途」分组；磁盘路径与 id 不变。

**Q：软件会按文件名里的 L1T / L2P 自动分层吗？**  
A：不会。文件名只作条目 id。自动仅认：项目容器→L2、用户级 Cursor 规则→L0；其余进「未分类」，由你拖到 L0/L1/L2。

**Q：永久库「按项目归属」里为什么以前堆满「用户级」？**  
A：库磁盘登记曾默认标成 global。现已改为「永久库」桶；只有真与用户 Cursor 容器相关的才进「用户级」。

**Q：`.skill` 包（如 road-design-spec.skill）为何以前「容器中」没有？**  
A：旧扫描只认含 SKILL.md 的目录。现已支持 ZIP 形态的 `.skill` 文件；刷新或扫描建库后应出现在「容器中」。

**Q：启动还会每次都弹扫描吗？**  
A：不会。启动只加载台账快照，**不**自动弹扫描预览。需要时用顶栏「扫描建库」；确认前不会静默挪文件。

**Q：我已经有库在别的盘，会不会被改到 C 盘？**  
A：只要以前已经配置过永久库，就不会自动改成 `C:\CursorSkills`。

**Q：放入之后 Cursor 里还是看不到？**  
A：先确认选对了容器。对 **skill** 等：用户级 `~/.cursor` 或项目 `.cursor` 放入后一般即可。对 **rule（规则）**：用户级 `~/.cursor/rules` **当前不会**被 Cursor 当作全局 Rule 加载（界面「容器中」在通用·Cursor 下会黄条提示）；跨项目请把正文复制到 **Cursor → Settings → Rules**；仅当前项目需要时，放入该项目的 `.cursor/rules`，并在 Cursor Rules 面板确认为 Always Apply。原理见 [01 §5.3](01-核心逻辑.md)。

**Q：「缺失」是什么？怎么找回或清掉？**  
A：台账里还有这条，但永久库文件和容器路径都找不到了（多为误删或有意删除）。**误删**：右键「打开曾用路径」到上级目录，查询回收站恢复后点「刷新」。**有意删除**：选中后点节标题旁或右键「清理缺失」，只删台账记录、不再显示，**不会**恢复文件。

**Q：删了 `catalog.json` 再扫描，点「稍后归类」为何台账又出现了？自动归类还有意义吗？**  
A：扫描建库会**立刻**重建台账（登记资产/项目）；弹窗出现时建库已完成。「稍后归类」只表示**不写入**层级/用途标签，**不撤销** `catalog.json`。自动归类仍有用：批量写标签方便分组；不写也可之后拖拽定级。详见 [CursorSkills/007](../../../CursorSkills/007-CCM自动归类建议如何产生-2026-07-27.md)。

**Q：详情「Markdown」打开报错或空白怎么办？**
A：若红条含 `Context "nodes" not found`，多为开发态（`npm run dev`）Milkdown 模块重复；请退出开发进程、删除项目下 `node_modules/.vite` 后重开，并确认已连开多个页签仍正常。生产试跑（`npm run build` 后 `npm start`）一般无此问题。其它空白可先看「原文」是否有内容；有内容则点红条「重试」。机制说明见开发者文档 Research/012。

**Q：详情「Markdown」和 HYmd 有什么差别？**
A：正文编辑器同为 Milkdown Crepe（所见即所得）；主题画廊已移植排版卡片、密度、mm 滑杆、布局与细节设置（纸面为简化版，无分页投影）。选中文字会出现浮动格式条（加粗/斜体/删除线/行内代码/公式/链接等，样式对齐 HYmd）；光标为 VS Code 风格竖条。顶部文档条显示正在编辑的文件；`Ctrl+S` 保存到**当前打开侧**（点「容器中」则写容器副本，点永久库则写库正本；`.mdc` / `SKILL.md` 的文首 YAML 会保留）。下划线/对齐/颜色扩展、Sheet、Slide、用户样式文件存取、分页纸面工厂等仍请用 HYmd。`.skill` 包（ZIP）在详情里只读，不可就地写回。

**Q：如何同时看容器副本和永久库正本并对比？**  
A：同一条目可分别从「容器中」与「永久库」打开两个 Markdown 页签（标题带「· 容器 / · 库」）。右键「对比容器与永久库」，或页签行右侧「对比」，会再开只读并排 Diff（左容器、右永久库）。两侧都须有可读主文件；对比页不可编辑，写回请用对应编辑签 `Ctrl+S`。

**Q：点「刷新」也会弹出同名冲突比对吗？**  
A：会。刷新会核对**当前活动容器**里仍存在的副本与永久库正本；内容哈希不同则弹出比对窗（并排 diff）。可选：保留库版覆盖容器、用容器覆盖库、另存新 id、或跳过。启动时仅加载快照，不会因此弹窗。日常只想看某一条目差异，用上一问的「对比」即可，不必整库刷新。

**Q：和旧版 WPF 数据兼容吗？**  
A：同一套 `%APPDATA%\CursorConfigManager\settings.json` 与库内 `catalog.json`，一般可直接接着用。

**Q：能不能一边开着本软件，一边大改 skills / rules 或手改 catalog？**  
A：改正文可以，但手改 `catalog.json` 或大规模挪库文件时请先退出本软件，否则刷新/操作可能把内存里的旧台账写回去。本软件只管路径与放入/移出，不负责改写 skill、rule 的文字内容。

**Q：同名 skill 在好几个目录都有，哪份算「最后优化」？**  
A：约定以**永久库里的那份为权威定稿**；容器里是当前生效的工作副本。移出/迁入永久库时若两侧内容不同，会弹出比对（哈希、大小、修改时间、预览）让你选保留哪边（不是 Git 完整版本历史）。原理见 [01](01-核心逻辑.md)。

**Q：放入容器后，永久库里还有这份文件吗？**  
A：有。「放入」是**复制**到容器，永久库正本保留。移出时若未改过容器副本则静默删容器侧；若改过则弹窗让你选留哪一版。

**Q：以前的「恢复初始」去哪了？**  
A：已移除。双份态下要把条目放回某容器，用「放入」或「曾用于本容器」再放入；容器与库内容不同用「刷新」比对决议。本软件不提供正文时光机。
