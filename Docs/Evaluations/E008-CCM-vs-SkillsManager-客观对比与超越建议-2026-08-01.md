# E008：CCM-Tauri2 vs Skills Manager 客观对比与超越建议

> **结论先行（建议）**：两产品**不是同一主战场**——Skills Manager（技能管理器，开源桌面+CLI）赢在「多工具装机、市场、Preset、多机备份」；CCM-Tauri2（CursorConfigManager Tauri2，本机配置台账管理器）赢在「永久库≠生效、哈希冲突人选、rules/skills 等同管、开源检疫」。  
> **超越路径**：不要正面拼「15+ Agent 一键矩阵 + skills.sh 完成度」，而要把 CCM 的台账语义做成**行业默认心智**（冲突可决断、检疫可晋升、多类型资产一账），并补齐易用与发行短板，直到「多项目定稿对账」场景体感明显优于 Skills Manager。

## 1. 一句话定位对照

| | CCM-Tauri2 | Skills Manager |
|---|---|---|
| **干什么** | 散落配置进**永久库**记账 → 按需**部署**到工具**容器**；开源先入**网络库**检疫再晋升 | **中央技能库**安装 → **Preset**/卡上角标 → **symlink/copy** 同步到多 Agent |
| **权威源** | 永久库 + `catalog.json`（台账 SSOT） | `~/.skills-manager` + SQLite 元数据 |
| **生效语义** | 库内不生效，容器才生效 | 同步到 Agent 目录即生效 |
| **不做** | Git 完整版本树、自建中央市场、网络库直部署 | （产品上）不以「哈希对账台账」为叙事中心 |

## 3. 五维评分（加权对照）

权重与 CCM Research/02 对齐：功能 0.25 · 易用 0.30 · 可靠安全 0.20 · 稳定 0.15 · 差异化 0.10。分 1–5。

| 维度 | CCM | SM | 说明（含证据级别） |
|---:|---:|---:|---|
| 功能 | 4 | 5 | SM：市场+Preset+多工具+备份+CLI 面更全（**已验证**功能清单）。CCM：台账/部署/对账/多类型/网络库检疫深（**已验证** Docs） |
| 易用 | 3 | 4 | SM：发版成熟、角标一键装、Preset 心智简单（**推断**+文档）。CCM：库/容器/网络三层学习成本高，GUI 部分待手测（**待验证**） |
| 可靠安全 | 4 | 3 | CCM：哈希对账、检疫、禁静默污染永久库（**已验证**机制）。SM：symlink/快速同步便利，定稿权威弱于 CCM 叙事（**推断**） |
| 稳定 | 3 | 4 | SM：1.28.x 连续发版与 CI（**已验证**）。CCM：主力壳迁完，发行冷启/大库秒表待验证（**待验证**） |
| 差异化 | 5 | 3 | CCM：库≠生效 + 哈希人选 + 多类型台账（**已验证**定位）。SM：差异在广度与生态，但赛道拥挤（**推断**） |
| **加权** | **3.70** | **4.05** | 总分 SM 略高；**定稿对账场景**下 CCM 可反超（见 §5） |

加权公式：Σ 分×权重。本表为**全功能桌面技能管理**视角；若只评「多项目同名冲突可决断」，CCM 应上调功能/易用权重后的观感（**建议**场景加权，见下）。

### 场景加权（建议：按你的真实痛点）

| 场景 | 更合理赢家 | 理由 |
|---|---|---|
| 多 Agent 一键装社区 skill | **SM** | 市场+adapters |
| 多机同步同一套 skills | **SM** | Git merge |
| 多项目 rules/skills 分叉、要定稿 | **CCM** | 台账+哈希冲突 |
| 开源 skill 先试看再进定稿 | **CCM** | 网络库检疫 |
| Agent 自动化改库（脚本） | **SM** | CLI + manage-skills |
| 只要 Cursor 本地整理 | 二者皆可；CCM 更深 | 类型更全 |

## 4. 机制对照（短表）

```text
Skills Manager:  [市场/Git/zip] → 中央库(~/.skills-manager) → symlink/copy → 各 Agent 目录
                 Preset = 一组技能的一次性激活

CCM-Tauri2:      [Git/基线] → 网络库(只读) → 晋升 → 永久库+catalog → 部署(复制) → 焦点容器
                 刷新对账；异哈希 → 人选（库/容器/另存）
```

| 概念 | CCM | SM |
|---|---|---|
| 库 | 永久库（权威，不生效） | 中央库（权威且待同步） |
| 生效 | 显式部署到容器 | sync / Preset / 角标 |
| 冲突 | 内容哈希三钮 | 合并/备份冲突流 |
| 开源输入 | 检疫层强制 | 安装即入库 |

## 5. 超越建议（给 CCM，可执行）

**总策略（建议）**：**错位超越**——在「定稿可信」上做成默认答案；在「装机广度」上只做**够用探测**，不复制 SM 全矩阵。

### 5.1 Must（不做则赢不了心智）

| # | 动作 | 为何能超越 | 验收 |
|---|---|---|---|
| M1 | **发行冷启可感知流畅** + 版本号统一（Docs/包号一致） | SM 用发版节奏建立信任；CCM 机制再好，装不上/慢=输易用 | 冷启秒表写入 04；包号单一真相 |
| M2 | **首次 5 分钟路径**：扫描 → 入库 → 部署 → 冲突演示（帮助或引导） | 降低「三层库」劝退；易用从 3→4 | 新用户脚本/帮助节可复现（可后补 06） |
| M3 | **冲突窗产品化打磨**：diff 可读、批量同策略、「传播到其它容器副本」闭环 | 这是相对 SM 的护城河；Research/02 已点名行业短板 | 假冲突为 0 的回归用例；多副本传播可测 |
| M4 | **网络库晋升漏斗**做透：基线/Git → 浏览 → 晋升 → 立刻可部署 | 用「检疫」打赢「装完难回滚」；不拼市场 UI | 有网主路径手测勾完（03 待验证项清零） |

### 5.2 Should（拉开差距）

| # | 动作 | 借鉴 SM 而不抄 | 边界 |
|---|---|---|---|
| S1 | **场景/Preset 轻量版**：命名「部署配方」（一组资产 → 一焦点容器），一次性应用 | 学 Preset 心智，但配方源=永久库，不改「库≠生效」 | 不做 live sync 伪装 |
| S2 | **只读 CLI**：`ccm status / deploy / refresh`（JSON）供 Agent 调用 | 学 SM CLI，守台账语义 | 勿让 CLI 绕过冲突窗默认静默覆盖 |
| S3 | **多工具路径表加宽到「常用 5～8」**（探测+部署） | 抄 adapters 列表作探测，不抄市场 | Won't：15+ 一键矩阵当主 KPI |
| S4 | **项目工作区一等公民**：多仓扫描结果 → 一键对账报告（谁与永久库漂移） | SM 有 Project Workspace；CCM 应输出「漂移清单」 | 报告 > 花哨矩阵 |
| S5 | **开源形态决策**：MIT + 公开核心（对齐 E001「CCM 社会主投」） | SM 用 MIT+社区获星；CCM 用文档与机制获信任 | 勿 AGPL 混栈；永久库路径说明清晰 |

### 5.3 Could（锦上添花）

- 活动日志导出（SM 有；利于排障）  
- 托盘/updater（发行后）  
- skills.sh **仅作网络库输入源**，结果仍进检疫（已有方向，保持单向）  

### 5.4 Won't（做了反而输）

| 禁止 | 原因 |
|---|---|
| 做成第二 Skills Manager（市场首页 + 角标矩阵 KPI） | 稀释差异化；跟发版/社区打消耗战 |
| 网络库直部署 / 静默改永久库 | 自毁检疫叙事 |
| 用 symlink「库=生效」取消部署步 | 变成薄同步器，CCM 无存在理由 |
| 三壳并行（Electron/Tauri/Wails）长期抢精力 | E001 已判；Tauri2 单线打穿 |

### 5.5 90 天目标（建议）

```text
Q：用户在「多项目同名 rules 分叉」场景下，是否毫不犹豫选 CCM？
A：若 M1–M4 + S1/S4 落地 → 是；若只加功能清单不打磨冲突/引导 → 仍输给 SM 易用。
```

| 里程碑 | 内容 |
|---|---|
| D30 | 版本号统一；冲突+对账回归绿；全局工作区 GUI 手测勾完 |
| D60 | 5 分钟引导或帮助；网络库有网主路径绿；漂移报告 MVP |
| D90 | 部署配方（轻量 Preset）；只读 CLI；决定是否 MIT 公开 |

## 6. 若目标是「用 Skills Manager、冻结 CCM」？

**结论（建议）**：仅当你的痛点 **>70% 是多工具装机与多机同步**、且几乎不碰「同名多版定稿」时，可主用 SM、CCM 降为自用台账。  
若你长期维护多仓 rules/skills 并害怕开源污染定稿——**应继续投 CCM**，用 §5 错位超越，而不是功能对标抄 SM。
