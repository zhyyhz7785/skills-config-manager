### 2026-07-30（统一同名冲突覆盖逻辑）

- **根因**：冲突弹窗三钮语义在四条路径不一致——撤回把 `merge`/`overwrite` 写成同一分支（都用容器盖库）；扫描建库把 merge/saveAs 也当成覆盖库；迁入 overwrite 整路径拷贝会破坏「库=文件 / 容器=目录」
- **修复**：抽出 `content_sync`（可比主文件 + 互拷 + 哈希校验）；撤回/扫描/迁入与刷新对齐
  - 保留永久库（merge）：库不动；刷新/扫描把库同步到容器；撤回/迁入删容器副本
  - 保留容器（overwrite）：容器主文件写入库并校验；撤回/迁入再删容器
  - 另存为（saveAs）：新 id 新条目，原库不动
- `npm run verify:tauri`：**已验证** 63 tests 通过

### 2026-07-30（刷新后冲突窗不消失）

- **根因**：磁盘已对齐再点「刷新」，后端返回空冲突，前端未 `setConflicts(null)`，旧比对窗仍显示过期 diff
- **修复**：无冲突时关闭冲突窗并 Toast 刷新结果；冲突哈希改走主文件 comparable 路径

### 2026-07-30（保留永久库间歇失效）

- **根因**：刷新冲突 `merge` 整路径拷贝，skill「库=SKILL.md / 容器=目录」时主文件未对齐；成功后打开的 Markdown 页签仍保留脏缓存
- **修复**：主文件级互拷 + 哈希校验；冲突成功后强制 remount 受影响页签并清 dirty
- 冲突窗注明：「保留永久库 = 用库覆盖容器」

### 2026-07-30（永久库「容器中」误标）

- **根因**：`isInActiveUse` 只要台账 `deployedPath` 在任意磁盘存在就绿标「容器中」，其它项目（BenchProj 等）的部署也会误亮
- **修复**：仅当 `find_live_path` 落在**当前活动容器**时标「容器中」；别处部署仍显示「台账有部署路径」但不加绿标

### 2026-07-30（规则扁平布局对齐）

- **根因**：入库写嵌套 `rules/{id}/{name}.mdc`，部署写扁平 `rules/{basename}`，列表副标题贴 `libraryPath` → UI 像有文件夹、容器里可能只有扁平文件

- **扫描**：容器 `rules/` 递归发现 `.mdc`；`find_live_path` 探测扁平/嵌套
- **副标题**：「容器中」优先显示相对容器的实测路径
