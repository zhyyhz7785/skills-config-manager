# CCM（Cursor 配置与技能库管理）产品调研与实现路径

> 调研日期：2026-07-31  
> 目标形态：桌面（Win 优先；Mac/Linux 可延）  
> 一句话目标：帮多工具、多项目的个人开发者，把散落的 skills / rules 等收到本机永久库记账，再按需放入工具真正读取的容器。

## 总论

**结论（建议）**：CCM（CursorConfigManager，本机配置资产管理器）应坚持「永久库 = 定稿权威、容器 = 生效副本、哈希冲突人选」三条锚点，做成**离线优先的桌面台账型管理器**；与 Skills Manager / Praxl 等「多 Agent 一键同步 + 市场」错开——不拼装机量与市场，而拼对账可信、规则/技能同管、同名多版本可决断。当前仓已是 Tauri 2 自研路径，最优是**继续深化差异化**，而非 Fork 或迁 SaaS。

## 0. 目标与约束

**结论（假设+已验证）**：用户画像与机制以本仓 [01-核心逻辑](../01-核心逻辑.md) 为准（已验证文档口径）；竞品事实来自官网/GitHub（已验证检索）；未实测对方软件标 **待验证**。

- 核心功能：扫描建库、永久库台账、部署/撤回、刷新对账、同名内容冲突决议（保留库 / 保留容器 / 另存为）
- 目标用户：长期维护多套 Cursor / Claude / Codex 等配置的个人开发者（假设：付费意愿低，更吃开源/自用）
- 平台形态：桌面客户端（本仓 Tauri 2）；不优先 Web/移动
- 关键约束：离线本机；纯 Tauri（无 Electron sidecar）；对比期与 Electron 主仓数据隔离
- 成功标准：用户能在「多项目散落」下 5 分钟内完成扫描→入库→部署，且冲突决议后磁盘与 UI 一致（待验证：正式发行冷启与更大库）
- 五维权重：功能 25% / 易用 30% / 可靠安全 20% / 稳定 15% / 差异化 10%（合计 100%；工具类偏易用）

## 2. 五维度分析

**结论（推断）**：加权领先者是 Skills Manager（覆盖与产品完成度）与 Praxl（版本史与团队/AI）；普遍短板是「同名多副本冲突的人类可读决议」与「永久库≠生效」语义弱——多为 symlink/覆盖同步。CCM 在差异化与可靠对账上可打高，在市场/多工具广度上落后。

### 汇总对比

| 竞品 | 功能 | 易用 | 可靠安全 | 稳定 | 差异化 | 加权总分 | 总评（含证据级别） |
|---|---|---|---|---|---|---|---|
| Skills Manager | 5 | 4 | 3 | 4 | 4 | **4.15** | 桌面+市场+多工具最完整直接对手（推断，未本机实测） |
| Praxl | 5 | 4 | 4 | 3 | 5 | **4.15** | 云/自托管+版本史+AI；AGPL 与在线假设（已验证定价页） |
| AIS（ai-rules-sync） | 4 | 3 | 4 | 4 | 3 | **3.55** | Git+symlink 适合团队规范分发（推断） |
| SkillManager（A-Duang） | 4 | 4 | 3 | 3 | 3 | **3.50** | 矩阵视图清晰，偏同步装机（推断） |
| Manage My Skills | 3 | 3 | 4 | 3 | 3 | **3.20** | 强调冲突备份，产品声量较小（推断） |
| CCM（本产品） | 4 | 3 | 4 | 4 | 5 | **3.85** | 台账+哈希冲突+库/容器分离是护城河（本仓机制已验证；发行体感待验证） |

加权 = 功能×0.25 + 易用×0.30 + 可靠安全×0.20 + 稳定×0.15 + 差异化×0.10。

### 头部竞品要点

### Skills Manager
- 优点：多工具同步成熟；市场与中央库一体；Tauri 2 技术栈与本仓接近
- 缺点：以「装到各 Agent」为中心，同名内容 diff 人选弱于 CCM 叙事；★与 issue 体量大，跟进成本高
- 评分：功能 5 · 易用 4 · 可靠安全 3 · 稳定 4 · 差异化 4

### Praxl
- 优点：版本历史与回滚；双向云同步；团队与 AI 审阅
- 缺点：Cloud 有配额；自托管 AGPL-3.0（若提供网络服务须开源衍生，合规成本高）；非纯离线桌面
- 评分：功能 5 · 易用 4 · 可靠安全 4 · 稳定 3 · 差异化 5

### AIS / CCM
- AIS：强在 Git 单一真相源与多类型（rules/skills/commands）；弱在无桌面对账 UI
- CCM：强在 catalog 台账、双份哈希冲突窗、项目扫描；弱在市场与「一键 15+ Agent」广度

### 行业现状小结
- 普遍做得好：中央库 + 多工具路径探测 + 从 Git/市场安装
- 普遍短板：容器侧多项目同名副本长期分叉时，缺少「预览 diff → 保留一侧 → 传播到全部副本」的闭环（本仓已朝此修，待长期验证）

## 3. 我应当做的产品

**结论（建议）**：为「多项目、多容器、要定稿权威」的个人开发者提供**离线台账型配置资产管理**，区别于 Skills Manager / Praxl 在于**库≠生效 + 哈希冲突人选 + rules/skills 等同管**。

- 机会矩阵 / 切入空白：高频痛点「同名多版不知哪份定稿」× 竞品满足度偏低 → 主切入点；「装社区技能」已红海 → 不做主战场
- 一句话定位：为【多工具多项目个人开发者】提供【永久库台账与容器对账】，区别于【Skills Manager / Praxl】在于【冲突可决断、离线本机、库与生效分离】
- 目标用户画像：主= Cursor 重度 + 多仓库规则维护者；次= Claude/Codex 双开者（不需要市场）
- MVP 功能集（MoSCoW：Must/Should/Could/Won't，按优先级切割范围）：

| 优先级 | 含义 | 功能 |
|---|---|---|
| Must | 没有它产品不成立 | 扫描建库、台账、部署/撤回、刷新对账、冲突三钮、规则扁平布局 |
| Should | 重要但可后补 | 台账五槽备份调入、多工具容器探测加宽、性能与大库 |
| Could | 锦上添花 | **只读网络库橱窗**（见 [Plan/03](../Plan/03-网络库与开源获取-2026-07-31.md)）；预设场景切换 |
| Won't(now) | 本期明确不做 | 云协作团队库、AI 改写 skill、移动端、取代 Git 版本树、**自建中央市场后端**、**网络库双向云同步 / 多 Agent 一键装机矩阵** |

- 非功能目标：冷启与刷新可感知流畅（待验证秒表）；冲突决议后二次刷新无假冲突（本轮调试已验证一案）；ACL（Access Control List，Tauri 命令白名单，作用是限制前端可调后端命令）命令齐全
- 差异化锚点：① 库/容器语义 ② 内容哈希冲突窗 ③ 台账 SSOT（Single Source of Truth，单一事实来源）
- 不做清单：不做**自建**技能市场门户与云账号；不做「只 symlink、不对账」的薄壳同步器；**允许**本机只读网络库作开源检疫橱窗（Plan/03），且晋升永久库后才编辑/部署
- 机会矩阵补充：**装社区技能**红海仍成立，但「官网/Git → 检疫 → 定稿对账」是可做的窄桥，不与 Skills Manager 正面拼市场 UI

## 4. 最优实现路径

**结论（建议）**：构建方式选**继续自研 Tauri 2 深化**；备选「借鉴 Skills Manager 的多工具路径表作探测扩展」，不 Fork 整仓。高风险：把网络库做成第二市场会稀释差异化；AGPL 依赖若混入发行需单独合规审查。

- 构建方式：推荐【自研延续】；网络输入用独立适配器，**禁止**链入 AGPL（如 Praxl 栈）
- 路线图：
  - MVP（现状加固）：冲突语义、假冲突、ACL — 部分已验证
  - V1：多工具容器探测、大库性能、发行包 — 待验证
  - V1.5 / 并行：[Plan/03](../Plan/03-网络库与开源获取-2026-07-31.md) 网络库 P0–P1（官网 + Git URL → 晋升）— 待验证
  - V2：公开索引热度排序等 Should — 待验证
- 风险补充：网络库心智占位 → 文案强调检疫/晋升；源 API 不稳 → Git URL 为 Must 保底

## 5. 结论

**结论（建议）**：台账型 CCM 锚点不变；网络能力按 Plan/03 做只读橱窗与单向晋升，不拼市场与双向云同步。
